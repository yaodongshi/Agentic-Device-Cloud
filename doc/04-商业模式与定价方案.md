# Agentic Device Cloud（ADC）Odoo 双版本开源模型商业模式与定价方案

## 一、结论摘要

- **推荐商业化结构**：ADC 采用 Odoo 式双版本开源模型——社区版 CE 以 LGPL-3 免费开源（边缘 SDK 保持 Apache-2.0；wire 协议、设备连接器、MCP 聚合、基础 HITL 单级审批、单机部署随 CE 发布），免费自部署且不限制设备数；企业版 EE 以商业许可按"EE 订阅（按设备/用户）+ EE 模块"叠加交付（管理控制台、多租户 RBAC/SSO、审计中心、多级审批、集群 HA、LLM 网关计量、配额限流、私有化包、等保模块、OEM 白标），EE 源码对订阅客户开放可见、可审计、可二开，但禁止再分发；通过"EE SaaS 订阅 + 设备阶梯 + EE 模块 + Token 增值""私有化买断 + 年维护费""OEM 白标授权"三类方式收费，全球以美元基准定价，分层靠功能断层与商业许可双重实现（以下所有价格为假设，需经定价实验验证）。
- **关键财务指标预估**（假设）：企业版 SaaS 典型客户（100 台设备）年合同额约 8 万元；毛利率约 70%；CAC 约 8 万元；LTV 约 28 万元；LTV/CAC 约 3.5；回收期约 17 个月；NRR 约 115%；企业版私有化首年合同额约 60 万元。

**社区版与企业版的转化关系（开源漏斗）**：

1. **下载**：CE 将评估门槛降为零，开发者、设备商、工厂 IT 可免费接入验证；
2. **部署**：单机自部署跑通首个场景（单厂区、少量设备、单级审批），此时社区版完全够用；
3. **功能断层**：业务扩展时撞上 EE 附加模块——多厂区要控制台与多租户、产线级可靠性要集群 HA、集团内控要多级审批、合规要审计中心、AI 成本管控要 LLM 网关计量与配额限流；升级 EE 后客户获得模块源码，可审计、可二开以满足自身定制，但按商业许可不得再分发；
4. **付费升级**：转化为 EE SaaS 订阅或 EE 私有化买断。

**社区版 CE 为何天然只适合小规模自用**：LGPL-3 与 Apache-2.0 一样允许商用，法律上不能限制商用与设备数，分层只能靠功能断层与商业许可实现——CE 无管理控制台与多租户，无法统一治理多厂区；无集群 HA，无法承载产线级可靠性；无多级审批与审计中心，无法满足集团内控与合规；无 LLM 网关计量与配额限流，无法控制 AI 调用成本。EE 以"CE 底座 + 附加模块"叠加交付，客户拿源码可审计可二开但不能再分发。设备规模一旦超出单机承载与单人治理能力，升级 EE 是唯一出路。原方案"社区版最多 5 台设备"的表述废止：开源许可下该限制不可执行且无法律意义，由功能断层与商业许可叠加替代其分层职责。

## 三、价值锚点分析

定价锚定价值而非成本。ADC 对离散制造客户的可量化价值点、开源版覆盖与缺失、企业版收费依据如下：

| 价值点 | 量化方式 | 社区版 CE 的覆盖与缺失 | 企业版 EE 为什么值钱 | 付费意愿 |
|--------|----------|----------------------|------------------|----------|
| 减少非计划停机损失 | 单台 CNC 停机综合成本 500-2000 元/小时（假设：含机时产出损失、操作工等待、在制品报废与交付延期罚金）；100 台设备、年非计划停机 50 小时/台，预测性维护与快速诊断减少 10%，年节省约 5000 台时 × 500-2000 元 = 25 万-100 万元 | 覆盖：单机基础 HITL 与诊断能力可处理单点故障；缺失：无集群 HA，平台自身宕机反而制造停机，无配额限流防连锁过载 | 集群 HA 保证高可用，多级审批保证故障处置链不中断，直接对应"停机损失"这一最强锚点 | 高 |
| 缩短 Agent 应用接入设备周期 | 传统点对点集成单设备 1-4 周（假设），MCP 标准化后 1-3 天；按集成工程师综合成本 2 万元/月（假设），100 台设备节省一次性成本 40 万-190 万元 | 全覆盖：SDK、wire 协议、连接器、MCP 聚合全部开源，接入效率价值开源版即可享受 | 企业版在该价值点上不收费——此价值点贡献获客流量而非收入，是"开源创造流量"的主力 | 高（获客价值） |
| 降低高危误操作风险 | 一次撞刀、急停误触或工艺参数覆盖事故单次损失约 1 万-50 万元（假设）；HITL 强制审批使高危调用全经人工核实，属"保险"型价值 | 覆盖：基础单级审批（单人确认）；缺失：多级审批（操作员→班组长→工艺主管）、审批策略集中管理、审计留痕 | 集团内控制度要求双人复核与多级审批链，社区版无法满足，多级审批与审计中心是明确付费理由 | 高 |
| 减少跨系统集成成本 | 传统 MES/ERP/AGV 点对点集成商报价 50 万-200 万元/项目（假设），统一虚拟 MCP 端点可降低 30%-50%，每项目节省 15 万-100 万元 | 覆盖：MCP 聚合开源；缺失：多租户隔离下的多厂区联邦端点 | 多厂区统一虚拟端点与租户隔离是集团级集成的前提，控制台与多租户是企业版独有价值 | 中 |
| 满足合规审计要求 | 设备操作全程留痕可直接输出审计报告，替代手工台账，节省合规人力约 0.5 人年（假设：约 6 万元/年） | 覆盖：基础操作日志；缺失：审计中心、180 天以上集中留存、等保模块、审计报告一键输出 | 审计中心与等保模块直接对应等保与客户内审要求，是企业版独占的合规价值 | 中 |

最强价值锚点仍是"减少非计划停机损失"：客户年付 8 万元，对应挽回损失下限 25 万元/年，投入产出比约 1:3 以上。CE 覆盖的是"接入效率"价值（负责获客），EE 独占的是"治理、可靠性、合规"价值（负责收费）——这正是 Odoo 式双版本开源的价值切分逻辑。

## 四、计费模式对比与推荐

| 模式 | 适用条件 | 客户可预测性 | 收入可预测性 | 销售摩擦 | 推荐度 |
|------|----------|--------------|--------------|----------|--------|
| 纯订阅（席位/租户） | 标准化软件、决策者预算制 | 高：费用固定 | 高 | 低 | 中 |
| 按设备数计费 | 价值与设备规模强相关的工业场景 | 高：费用随装机数可预估 | 高：随客户扩容自然增长 | 低：与车间台账直接对应 | 高 |
| 按 Token 计量 | 大模型调用波动大、需精细化控制 | 低：月度账单波动引发财务质疑 | 低：随用量波动 | 高：需解释计量口径 | 中 |
| 按审批工单计费 | HITL 场景 | 低：工单量难预估，客户会因"怕花钱"绕过安全流程，与安全价值冲突 | 低 | 高 | 不推荐 |
| 混合（订阅 + 设备阶梯 + Token 增值） | 工业平台型产品 | 高：固定部分占 85% 以上，Token 部分可设月上限 | 高 | 中 | 推荐 |

**推荐结论**：混合计费——"平台订阅费（含基础设备额度）+ 设备授权阶梯价 + LLM Token 计量增值（可选，可设月度封顶）+ 私有化买断与年费"。理由：设备数作为主计量单位最贴合工业客户心智与价值分布；Token 仅作增值项并支持客户自带模型密钥（BYOK），避免因成本波动引发账单争议；按审批工单计费被否决，因为它会激励客户关闭审批绕过安全，与产品安全价值主张直接冲突。

**双版本开源模型特有考量——社区版 CE 免费会不会侵蚀付费版**：不会，靠功能分层与商业许可双重回答。其一，CE 仅覆盖"单机接入与基础 HITL"，无法提供多租户控制台、集群、审计中心与计量——对目标客户（20-500 台设备的中型企业与集团）而言 CE 不满足生产级要求，侵蚀的不是付费意愿而是付费前的评估成本；其二，免费降低的是获客成本而非客单价，CE 试用者越界后要么自建企业功能（成本远高于订阅），要么升级付费；其三，防线纪律是"EE 模块坚决不进 CE 仓库"，任何顺手把治理能力下放 CE 的做法都会击穿分层。CE 零收入但创造获客流量、生态贡献与 OEM 采用，其回报体现在 CAC 下降与渠道扩张，而非直接收入。

**定价锚定逻辑**：典型 100 台设备客户 EE SaaS 年费 = 3.98 万 + 80 台 × 400 元 = 7.18 万元，加 Token 增值后约 8 万元/年（EE 附加模块为增量收入，按模块另计，假设，不改变上述基准口径）。私有化首年约 60 万元的高端锚点使 SaaS 显得便宜；CE 免费则挡掉试用流量。

**分层关键点（替代原"社区版限 5 台"）**：CE 无授权设备数限制，分层靠功能断层与商业许可双重实现。LGPL-3 允许任何规模商用，"限台数"条款在法律上不可执行；正确做法是让组织级与规模化能力（控制台、多租户、集群、审计、计量）只以 EE 附加模块交付（EE = CE + 附加模块），模块源码对订阅客户可见但禁止再分发，当设备规模超过单机承载与单人治理能力时，客户自然升级。

**企业版 EE SaaS 为何是主销版本**：离散制造中型企业是 ADC 首发目标细分市场的主体（数据暂缺，属结构性假设）；SaaS 形态交付周期短（1-2 周上线）、无需客户自建运维、现金流为年预付制；EE 订阅 + 设备阶梯 + EE 模块附加价使客单价随客户数字化扩张自然增长，是 NRR 的主要来源。私有化客单价高但销售周期长（6-12 个月），定位为利润放大器而非收入主力。CE 是漏斗入口，本身不承担收入目标，其 KPI 是下载量、部署激活率与转化率而非销售额。

**全球定价（美元基准 + 本地化）**：

- **定价货币基准**：以美元为全球基准价，中国大陆以人民币定价；人民币/美元汇率在 6.8-7.3 区间内价格不动，超出区间触发季度价格评估（假设）。
- **美元基准价（假设，需验证）**：EE SaaS 订阅约 5700 美元/年（按 3.98 万元、汇率 7.0 折算）；设备阶梯约 57/43/36 美元/台/年（对应 400/300/250 元）；EE 私有化买断约 7.1 万美元起（对应 49.8 万元），维护年费 20%；Token 增值约 0.014 美元/千 Token（对应 0.10 元）；EE 模块按模块年费另计。
- **海外定价假设**：海外 SaaS 客单价约为中国 1.5-2 倍（假设：发达市场支付能力、合规刚需与人力替代成本更高），实际海外价在美元基准价上按区域系数浮动；本地化价格锚定当地同类工业软件成交价，均为假设，需本地定价实验验证。
- **结算与防套利**：海外以美元或当地货币结算，区域 License 与结算币种绑定（防跨区套利，见风险章）。
- **落地节奏**：依托产品 i18n 国际化、原生 MCP 设备鉴权绑定与 A2A 协同调度能力，先覆盖英语市场（北美/东南亚，假设），再进入日韩与欧洲（假设），由本地化渠道伙伴承接交付。

**切分原则**：单机自用所需能力进 CE 仓库（LGPL-3，越底层越开放），组织级治理与规模化运营能力进 EE 模块仓（商业许可，源码对订阅客户可见、禁止再分发，越上层越收费）；LLM 网关计量既是成本中心又是计费依据，全量进 EE 仓；任何进入 CE 仓的功能默认放弃其直接收费权，入仓决定须经商业化评审。

## 七、License 设计

### 7.1 开源层许可（SDK 为 Apache-2.0，CE 为 LGPL-3）

- **SDK（Apache-2.0）**：边缘 SDK 以 Apache-2.0 发布，允许商用、修改与再分发，不限制设备数与部署规模，不收取授权费——最大化设备商嵌入采用。
- **社区版 CE（LGPL-3）**：wire 协议、设备连接器、MCP 聚合、基础 HITL 单级审批、单机部署以 LGPL-3 发布；免费开源、无订阅义务，允许商用与修改；对 CE 库本身的修改须回馈社区，但以链接方式使用 CE 不触发传染，保护 CE 底座不被 fork 后闭源吞噬，又不拖累使用方。
- **商标与品牌条款**：Apache-2.0 与 LGPL-3 均不授予 ADC 商标、Logo 与"ADC 官方认证"标识的使用权；fork 项目不得以 ADC 名义进行商业宣传；"Powered by ADC"字样仅限未修改版本使用。商标条款是防 fork 白嫖的第一道法律防线。
- **合规义务**：随分发保留 LICENSE 与 NOTICE 文件；每次发布随附 SBOM（软件物料清单，进 CI 自动生成）；贡献者须签署 CLA/DCO（防贡献者 IP 风险，见风险章）。

### 7.2 企业版 EE 商业订阅许可

- **许可性质**：EE = CE 底座 + EE 附加模块；EE 源码随订阅/买断对客户开放可见，可审计、可二开（修改仅限客户内部使用），商业许可授权使用、禁止再分发——代码透明性消除"黑盒闭源"疑虑，许可约束守住收入边界。
- **授权单位**：主单位为"在线设备数"（以设备心跳注册为准，按自然月峰值计）与"EE 订阅用户数"（参考 Odoo per-user 结构，假设）；私有化副单位为"租户数/厂区数"与"设备规模包"；审批人/工程师席位不另行收费，避免多重计量引发销售摩擦。
- **期限**：SaaS 订阅 1 年，自动续费；私有化买断为永久使用权，维护年费逐年续订。
- **续费**：到期前 90 天启动续费流程；年费涨幅原则上不超过 8%（假设），超额涨价需提前 180 天书面通知。
- **升级抵扣**：CE 升级 EE SaaS 按当月剩余天数折算抵扣；SaaS 阶梯内扩容按实际超出台数补差价；SaaS 转私有化，已付订阅费的 50%（假设）可抵扣买断款。
- **禁止再分发**：EE 源码仅限授权客户内部使用；未经书面同意不得再分发、转售、出租、分许可或基于 EE 源码形成派生商用产品；企业版随客户资产并购转让需经书面批准并重新签订；禁止 OEM 白标再销售（需另签渠道协议并支付授权费）。
- **防滥用 License 心跳计量**：云端 License 服务按设备心跳实时计数；允许 10% 超额缓冲，超出部分次月账单按实结算；私有化离线宽容期 7 天（假设），逾期未回传计量数据则功能降级为只读；订阅到期或解约后，客户对 EE 源码的访问权回收，已交付源码按许可条款处置。
- **合规审计**：客户须保留计量数据并允许 ADC 每年一次远程或现场审计；审计发现超额使用 30 天内补缴差价；审计日志与 HITL 工单数据属客户资产，ADC 仅作匿名化聚合用于产品改进（须与隐私合规条款衔接）。
- **违约罚则**：私有化超装或未授权厂区部署，违约金为授权额的 3 倍（假设）；EE 源码外泄或向非订阅方再分发按侵权追责，罚则为授权额的 3 倍（假设）；严重违约 ADC 有权终止授权并停用 License 服务。

## 八、商业画布（九要素）

- **客户细分**：大陆离散制造企业（CNC/PLC 场景）三类——信息化基础较好、已有 Agent 应用尝试的先锋工厂（首攻，企业版 SaaS）；有安全合规刚需的集团与敏感行业（企业版私有化）；设备制造商与集成商（社区版与 SDK 培育，OEM 白标对象）。
- **价值主张**：把物理设备变成标准 MCP 工具节点，让 Agent 应用"说人话"即可调度设备；CE 使接入零门槛，EE 让 AI 控制硬件可治理、可审计、可合规。
- **渠道**：开源社区与 SDK 分发（主渠道：GitHub 仓库、文档站、设备商 SDK 集成嵌入）；开发者社区与技术内容（MCP 生态曝光）；海外开源社区与本地化渠道（国际化阶段，依托 i18n 与本地交付伙伴）；直销售前工程师 + 销售试点（前 3 个客户）；设备商/集成商转售与 OEM 白标；行业展会与代理商网络（规模化后）。
- **客户关系**：社区版开发者自助 + 社区工单支持；企业版 SaaS 客户 CSM 与季度价值回顾；企业版私有化客户驻场陪跑式交付。
- **收入流**：企业版 SaaS 订阅年费（主收入）；设备阶梯授权（增长性收入）；Token 计量增值（毛利型收入）；私有化买断 + 维护年费（大单收入）；OEM 白标授权（渠道收入）；未来可扩展：HITL 审计报告增值包、行业 Agent 模板市场抽成。
- **关键资源**：CE/EE 双仓库与全球开源社区（获客流量与生态资产）；管理控制台、多实例网关与 HITL 引擎、审计中心（核心 IP，EE 模块仓）；LLM 网关计量与配额体系（计费基础设施）；商标与品牌资产（防 fork 的法律工具）；首批工业样板客户案例。
- **关键活动**：开源仓库维护与社区运营（issue 首响 24 小时、PR 合入 5 个工作日承诺）；CE/EE 功能切分纪律（防止 EE 模块流入 CE 仓库）；版本迭代（HITL 与计量是商业化命门）；样板客户交付与案例沉淀；定价实验与销售流程打磨。
- **关键伙伴**：LLM 供应商（模型接入，支持 BYOK 对冲成本）；设备商/集成商（渠道、现场交付与 OEM 白标）；企业微信/钉钉生态（审批触达）；开源贡献者与 MCP 社区（连接器共建）。
- **成本结构**：研发团队 5-8 人（假设：年人力成本 300 万-500 万元，含开源仓库维护投入）；社区运营与文档投入约 1 人年（假设）；云资源与 LLM 推理 Token（按量，转售加价覆盖）；销售与交付人力（约 2-4 人）；私有化交付差旅与驻场成本。固定成本以研发为主，可变成本以 Token 与交付为主。

## 九、单位经济模型

### 9.1 企业版单位经济（沿用原假设）

| 指标 | 数值 | 假设与计算过程 |
|------|------|----------------|
| ACV（企业版 SaaS 典型客户年合同额） | 约 8 万元 | 平台订阅 3.98 万 + 80 台 × 400 元 = 7.18 万，Token 增值约 1 万（假设：单客户月消耗约 800 万 Token） |
| 毛利率（SaaS） | 约 70% | 云资源与集群基础设施约 8%（假设：单客户月成本约 530 元）；LLM Token 转售成本约 8%（假设：加成 40% 倒推）；技术支持与 CSM 分摊约 12%；研发不摊入毛利。毛利率 = 1 - 28% ≈ 70% |

| CAC 回收期 | 约 17 个月 | 8/（8 × 0.7 / 12）≈ 17.1 个月（假设：年预付制下实际资金回收约 14 个月，因首年费用一次收取） |

**结论**：开源漏斗使整体获客成本下降——若 30% 新客来自社区渠道（假设），混合 CAC 约 6.5 万-7 万元，LTV/CAC 提升至约 4.0-4.3，回收期缩短至约 14 个月；开源侧真正的成本不是资金而是时间（社区冷启动约 12-18 个月，假设）。企业版单客户模型成立，LTV/CAC 约 3.5、回收期 17 个月在工业软件中属健康区间（对标工业 SaaS 回收期普遍 12-24 个月，属经验假设）；真正的风险在销售周期与试点折损，而非单价。

## 十、定价实验计划

**沿用原假设验证**：

1. 设备数计价（400 元/台/年）的支付意愿——是否会被与"每台设备买盒子的钱"比较而压价。
2. Token 增值计价的接受度——工业财务是否接受月度变动的账单，BYOK 是否被多数客户选择。
3. 企业版 SaaS 3.98 万元基础订阅是心理门槛还是过低——私有化 49.8 万元锚点是否有效。
4. 年预付 + 10% 折扣是否比年付原价更能锁定续费（假设：折扣为 10%）。

**新增开源相关假设验证**：

5. 社区版到企业版转化率：假设 1%-2%，需埋点验证"下载 → 部署激活 → 付费"真实漏斗；若部署激活率低于 5%，说明文档与 onboarding 投入不足，优先修文档而非降价格。
6. 免费是否影响付费意愿：社区转化客户被报价时的价格敏感度是否高于直销客户；若社区客户系统性要求更低折扣，调整社区渠道报价策略（保留原价但赠送实施工时，避免击穿价盘）。
7. 设备商嵌入 SDK 后的 OEM 白标意愿：验证 OEM 授权收入流的可行性（意向设备商数量、可接受授权费区间）。
8. 原"社区版限 5 台"假设废止后的替代假设：验证"单机自部署在多少设备规模下出现治理痛点"——即功能断层的真实位置（假设：超过 1 个厂区或约 50 台设备时触发升级诉求），据此校准社区版宣传口径与升级触达话术。

**验证手段**：

- **预售试点**：向 3-5 家先锋工厂提供两套报价方案（A：纯设备计价；B：低订阅 + 高 Token 计价）做对照成交实验，记录谈判阻力点与成交周期。
- **AB 定价页**：官网 SaaS 定价页对设备单价做 300/400/500 元三档随机分流，以"留资率 × 报价接受率"为指标，两周一轮迭代。
- **开源漏斗埋点**：仓库下载、文档站留存、demo 部署、License 申请四环节打点，按季度复盘转化率并修正漏斗假设。
- **客户访谈脚本要点**：过去一年因设备停机/误操作损失多少；设备台账在哪个部门、预算归属是 IT 还是生产；愿意为"一次高危误操作被拦截"付多少；现用工业互联网平台/点检系统年付多少；按设备数计价采购审批需要哪些材料；社区版试用后未付费的具体原因。
- **验证节奏**：第 1-2 季度完成 10 场深度访谈与 3 个预售试点；第 3 季度前根据数据修正定价表；任何一项指标连续 3 个客户拒绝同一点，即触发改价。

## 十一、商业模式风险与对策

| 风险 | 描述 | 对策 |
|------|------|------|

| EE 源码泄漏给非订阅方（新增） | EE 源码对订阅客户开放可见，存在客户或相关人员将 EE 源码扩散给非订阅方的风险 | 以许可约束而非技术约束兜底：EE 商业许可明确禁止再分发；源码按客户嵌入水印/哈希指纹便于溯源（假设）；违约追责与年度审计条款兜底（假设：罚则为授权额的 3 倍）；订阅到期回收源码访问权 |
| 全球定价与本地化套利（新增） | 海外客单价约为中国 1.5-2 倍（假设），存在跨境从低价区倒卖授权到高价区的套利风险 | 区域 License 与结算币种绑定；美元基准价 + 本地锚定价并监控异常低价渠道（假设）；渠道协议约束跨区转售并配违约条款 |
| 私有化客户转售与多厂超装 | 买断客户可能私下复制部署到未授权厂区 | License 心跳计量 + 以厂区为授权单位 + 年度审计条款 + 违约罚则（假设：违约金为授权额的 3 倍） |
| 大厂免费策略 | 华为、阿里等工业互联网平台以低价或免费入场 | 避开通用 IoT 数据采集红海，聚焦"设备即 MCP 节点"的 AI 原生编排细分；以交付速度与 HITL 安全差异化为卖点 |
| LLM 成本波动 | Token 成本随供应商调价挤压毛利 | Token 增值按成本加成 40% 定价并保留每季度调价条款；默认支持 BYOK 让客户自担模型成本 |
| 账期与现金流风险 | 工业客户付款审批周期长（假设：3-6 个月） | 年预付制为主；试点期收 30% 预付款；超 50 万元大单分阶段回款 |
