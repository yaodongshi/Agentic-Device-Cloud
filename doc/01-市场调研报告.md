# 市场调研报告：Agentic Device Cloud (ADC)

> 调研时间：2026-08-14；调研范围：中国 + 全球双主场（中国为 TAM/SAM/SOM 精算主口径，全球为定性测算口径，见 3.5）；数据口径：以 2025-2026 年为基年，展望至 2029-2032 年。
> 分级标注约定：【事实】= 有可溯源出处；【推断】= 基于事实的逻辑外推；【猜测】= 无数据支撑的主观判断。

---

## 一、结论摘要

- **判断：值得进入，但要打"窄而深"的仗，并从第一天起按"中国 + 全球"双主场布局。** ADC 所处的"AI 原生设备编排与治理平台"是一个正在打开的结构性新层：全球 IIoT 平台市场 2026 年约 125.5 亿美元、CAGR 12.8%（【事实】MarketsandMarkets），而 MCP 协议在 2024 年底发布后一年内被 OpenAI、Google 相继采纳并于 2025 年 12 月捐给 Linux 基金会（【事实】），设备侧"工具契约"标准化的窗口期是 2026-2028 年。地域判断：中国市场是 TAM 精算与灯塔客户主战场，但 MCP/A2A 生态本质是全球性协议生态（A2A 已进 Linux 基金会、百家企业支持，【事实】），海外中资工厂与欧美设备商构成第二主场，全球市场纳入正式测算口径（定性测算见 3.5）。两个新市场窗口叠加：a) 设备厂商开始把 MCP Server 运行时预置进设备的"原生 MCP 设备"浪潮（智能家居先行、机器人/工业设备跟进，预计 2027-2028 年起量，【推断】）；b) A2A 多 Agent 协作协议 2025 年发布并入 Linux 基金会后，"多 Agent 协同调度设备"的 Agent 协作层市场正在形成（【事实】+【推断】）。市场本身真实且增长确定，但中国工业互联网平台旧赛道已高度拥挤（【推断】），ADC 的差异化不在"平台"而在"AI Agent 闭环治理层"（HITL+NAT 穿透），应把稀缺资源压在离散制造 CNC/PLC 场景，同时以开源社区同步卡位全球开发者与设备商生态。
- **推荐首发细分：离散制造（机加工/3C 电子制造），企业级 B 端。** 该细分占全球 IIoT 平台市场 58.7%（【事实】MarketsandMarkets 2026 年数据），是规模最大、增速最高、且对 ADC 三大能力（反向穿透、设备工具化、高危操作人工审批）付费意愿最直接的场景（【推断】）。
- **规模判断（中国大陆、平台软件层口径）：TAM 约 120-140 亿元/年，SAM 约 25-35 亿元/年，SOM（第 3 年）约 0.15-0.3 亿元/年。** 自上而下与自下而上两条路径交叉验证差距约 1.3 倍，处于可信区间。全球口径定性测算（不重复三层精算）：设备编排与 Agent 协同层 TAM 约 50 亿美元/年、SAM 约 26-33 亿美元/年（2026，【推断】），约为中国 SAM 的 5-9 倍，见 3.5。
- **开源路线加速进入并降低信任门槛：Odoo 式双版本开源（CE 以 LGPL-3 免费开源、SDK 以 Apache-2.0、企业版 EE 源码可见商业许可）显著提升市场进入速度。** 工业客户采购周期长、信任建立慢，社区版免费自部署让工厂工程师先验证再谈企业版付费，可缩短试点启动周期；同时开源是出海门票，海外客户（东南亚中资工厂、欧美设备商与本地 IT 团队）可绕过国内销售体系直接评估产品，为第 3 年"开源国际化先行"铺路；社区以英文优先运营、中英双语首发（【推断】）。收入口径说明：社区版免费，收入来自企业版授权与增值（企业版 SaaS 订阅、私有化买断+年费、项目实施），不影响 SAM 口径——SAM 测算的仍是企业版可触达的付费支出。
- **风险主判词：付费意愿未证 + 窗口期有限。** 最大的不确定不是市场大小，而是中端制造企业是否愿意为"Agent 自主调度设备"这一新范式付费（【推断】），必须在 6 个月内用付费试点证伪或证实。
- **执行要义：小市场高渗透优于大市场低渗透。** 先拿下 50-500 台设备规模的中型机加工工厂做灯塔，再向中大型客户与海外市场复制（双主场并行，【推断】）。

## 二、市场定义与边界

**包含范围：**
- 产品形态：AI 原生设备编排与治理平台——面向未来原生内嵌 MCP Server 运行时的设备（设备鉴权绑定、开机即注册工具），支持多 Agent 协同调度编排设备（A2A 范畴），并提供 NAT 反向穿透、LLM 网关、HITL 人工审批熔断；全栈 i18n 国际化（英文+中文首发，面向全球市场）。
- 收入口径：企业版授权与增值收入——企业版 SaaS 订阅（按设备台数/租户）+ 企业版私有化授权（买断+年费）+ 项目实施与解决方案收入；不含传感器、网关等硬件毛利（硬件按生态伙伴口径）。
- 商业模式口径（Odoo 双版本）：边缘 SDK 与 wire 协议以 Apache-2.0 开源，平台社区版 CE 以 LGPL-3 开源、免费自部署；企业版 EE（多租户、HITL 合规审计、行业 Agent 场景等附加模块）为源码可见商业许可收费。社区版免费不改变本报告 SAM 口径——SAM 测算的是企业版可触达的付费支出，社区版主要贡献获客漏斗顶部流量而非直接收入（详见第 6、7 章），该口径说明已在结论摘要注明。
- 地域口径：中国 + 全球双主场。中国为 TAM/SAM/SOM 精算主口径（第 3 章三层数字均以中国口径计算，保持不变）；全球（北美/欧洲/东南亚及其他）纳入正式测算口径，以定性量级测算呈现（见 3.5），不重复三层精算。海外路径双轨：海外中资工厂（跟随出海）+ 欧美设备商与全球开发者（开源社区英文优先触达）。
- 时间口径：基年 2026，预测到 2029（TAM）、2032（全球参照）。

**排除范围：**
- 广义 IoT（消费级智能家居、车联网）。
- 工业互联网平台的"大而全"口径（含工业软件 MES/PLM、云基础设施、行业 PaaS 全部），本报告只取"设备连接与编排层 + AI Agent 协同层"。
- 设备本体与控制系统（CNC 数控系统、PLC 硬件）的销售收入。

**市场定义的一句话：** ADC 的市场 = 离散制造企业为"把设备变成 AI 可调用的受控工具"而支付的软件与订阅支出。

## 三、市场规模测算（TAM / SAM / SOM）

### 3.1 分层结论

| 层级 | 口径 | 规模（金额/年） | 测算方法 |
|------|------|---------------------|----------|
| TAM | 中国 IIoT 平台软件市场（设备管理、应用使能、连接管理三类平台，含服务） | 2026 年约 120-140 亿元人民币；2029 年约 200-250 亿元 | 自上而下（全球数据切到中国） |
| SAM | 中国离散制造行业设备编排与 AI Agent 协同平台层 | 2026 年约 25-35 亿元人民币 | 自上而下 + 自下而上交叉验证 |
| SOM | ADC 第 3 年（2028）可实现年收入 | 约 0.15-0.3 亿元人民币/年（占 SAM 约 0.5%-1%） | 自下而上（目标客户数 × 客单价 × 渗透率） |

### 3.2 自上而下测算过程

**TAM 推演（全球 → 中国）：**
1. 全球 IIoT 平台市场：2025 年 109.8 亿美元，2026 年 125.5 亿美元，2032 年 294.0 亿美元，CAGR 12.8%（【事实】MarketsandMarkets《IIoT Platform Market》报告 TC 6664，2026 年 9 月版）。
2. 亚太为增速最快区域（【事实】同上）；IIoT 整体市场中中国是亚太最大单一市场（【事实】MarketsandMarkets《Industrial IoT Market》SE 2909）。取中国占全球 IIoT 平台市场 12%-18%（亚太占比 35%-40% × 中国占亚太 35%-45%，【估算假设】）。
3. 汇率取 1 美元 = 7.2 元人民币（2026 年中枢，【估算假设】）。
4. 计算：125.5 亿 × 13%-17% × 7.2 ≈ 117-154 亿元；取保守区间 **120-140 亿元（2026，TAM）**。按 12.8% CAGR，2029 年约 170-200 亿元；考虑中国智能制造政策溢价，给出 200-250 亿元的宽区间（【推断】）。

**SAM 推演（平台 → 离散制造 → 编排层）：**
1. 离散制造（Discrete Industry）占全球 IIoT 平台市场 58.7%（2026 年，【事实】MarketsandMarkets TC 6664）。
2. 中国离散制造 IIoT 平台市场 = 120-140 亿 × 55%-60% ≈ 70-80 亿元（【估算假设】中国离散占比不低于全球水平，机床与 3C 制造密集）。
3. 平台三大类中"设备管理平台"为核心与最大单一类别（【事实】TC 6664 定性：device management 是部署必备层）；设备管理+连接+编排相关支出占平台总支出的 35%-45%（【估算假设】）。
4. AI Agent 协同层（MCP 工具化、LLM 网关、HITL 治理）作为增量预算，占编排层支出的 10%-15%（【估算假设】，参照企业 AI 预算向 Agent 基础设施迁移的趋势）。
5. **SAM ≈ 70-80 亿 × 40% × 1.1 ≈ 30-35 亿元/年（2026）。**

### 3.3 自下而上测算过程

**可服务设备池：**
1. 中国数控机床保有量约 600 万台（量级，【估算假设】：机床工具工业协会口径未在本次调研中检索到原始报告，该数字为公开报道常见量级，待采购官方数据复核）。
2. 其中可联网、具备改造价值的中高端设备占 25%-35%（【估算假设】，低端经济型机床联网 ROI 为负）→ 约 150-210 万台，取中值 180 万台。
3. 中国工业机器人保有量约 180 万台（【估算假设】：IFR 口径约 170-180 万台，未在本次调研中直接检索到原始报告），其中可纳入协同调度的约 30%-50% → 约 50-90 万台，取中值 70 万台。
4. **目标设备池合计 ≈ 250 万台（CNC 180 万 + 机器人 70 万）。**

**客单价（ARPU）：**
- 设备编排平台按台数订阅，行业参照：Samsara 类设备 SaaS 单设备月费 3-15 美元、国内 IIoT 平台单设备年费 300-3000 元不等（【估算假设】）。取 CNC 类设备年订阅 800-1200 元、机器人 400-800 元，加权平均约 1000 元/台/年。

**计算：**
- **SAM（订阅口径）≈ 250 万台 × 1000 元 ≈ 25 亿元/年。**
- 若叠加项目实施与解决方案收入（行业惯例约为订阅收入的 0.5-1 倍，【估算假设】），SAM 上限约 35-40 亿元，与自上而下口径吻合。

**SOM（第 3 年）：**
- 目标客户画像：设备 50-500 台的中型机加工/3C 工厂（中国此类工厂以万计，【推断】）。
- 第 3 年累计付费设备 5,000-10,000 台（相当于 30-80 个灯塔客户的渗透，【估算假设】），ARPU 800-1000 元 → 订阅收入 400-1000 万元/年。
- 加项目实施收入（订阅的 1-2 倍）→ **年收入 0.12-0.3 亿元，取 0.15-0.3 亿元（SOM），占 SAM 0.5%-1%。**

### 3.4 两种方法的差异及解释

自上而下 SAM 30-35 亿元 vs 自下而上 25 亿元，**差距约 1.2-1.4 倍，小于 3 倍阈值，无需强制归因**。剩余差距来源清晰：
1. 自下而上只覆盖了 CNC 与工业机器人两类设备，未含 PLC、AGV、传感器网关、检测仪器等（占真实设备池的另一半左右）；
2. 自上而下口径天然包含服务收入，自下而上的 25 亿元为纯订阅口径，叠加服务后两法收敛至同一区间。

**口径敏感度提示：** 若"AI Agent 协同层"预算被证明无法独立收费（客户只愿意为传统设备管理付费），SAM 将下修约 10%-15%——这正是第 7 章假设 1 的验证对象。

### 3.5 全球口径定性测算（量级区间，不重复三层精算）

**口径说明：** 本小节仅对全球市场给出量级区间，用于战略参照与资源配置；中国市场三层精算（3.1-3.4）数字保持不变，全球 SOM 不测算。

**推演（沿用 3.2 的同一套切分假设，属性全部显式标注）：**
1. 全球 IIoT 平台市场 2026 年 125.5 亿美元（【事实】MnM TC 6664，与 3.2 同源）。
2. 设备管理+连接+编排相关支出占平台总支出 35%-45%（【估算假设】，与中国口径同假设）→ 全球"设备编排层"TAM 约 44-56 亿美元/年（2026）。
3. AI Agent 协同层增量预算占编排层 10%-15%（【估算假设】，与中国口径同假设）→ 约 4-8 亿美元/年。
4. "设备编排 + Agent 协同"两层叠加的全球 TAM：约 48-64 亿美元/年（2026），量级表述为**约 50 亿美元/年**（【推断】）；按 12.8% CAGR 外推，2029 年约 70-80 亿美元（【推断】）。
5. 全球 SAM（离散制造 × 58.7% × 编排与协同层占比）：125.5 亿 × 58.7% × 40% ≈ 29 亿美元/年（2026），区间约 26-33 亿美元（【推断】）。

**战略含义：** 全球 SAM 约为中国 SAM（25-35 亿元人民币，约合 3.5-4.9 亿美元）的 5-9 倍（【推断】）。但海外市场结构与中国不同：欧美客户对开源治理类软件付费习惯成熟、A2A/MCP 生态由北美主导（【推断】），同时 Viam/Tulip 等玩家已存在（见竞品分析报告），ADC 应以开源社区与设备商 OEM 渠道切入海外，而非复制国内直销打法（【推断】）。

## 四、市场趋势

### 4.1 结构性趋势（标注驱动力与证据）

1. **MCP 正成为 AI 与设备互联的事实标准，工业设备侧窗口已打开。**
   驱动力：Anthropic 于 2024 年 11 月发布 MCP，2025 年 3 月 OpenAI 全产品线采纳，2025 年 4 月 Google 宣布采纳，2025 年 12 月 Anthropic 将 MCP 捐给 Linux 基金会下设的 Agentic AI Foundation（Anthropic、Block、OpenAI 共建）（【事实】Wikipedia/TechCrunch）。2026 年 4 月首届 MCP Dev Summit 北美场约 1,200 名与会者；Salesforce Headless 360 平台 2026 年 4 月上线 MCP 路由、5 月底累计处理 450 万次 MCP 调用（【事实】Wikipedia/InfoQ/Salesforce Ben）。
   判断：软件侧 MCP 已过拐点，下一步战场是物理设备侧（设备即 MCP Server）。工业界尚无事实标准制定者，2026-2028 年是设备工具契约层的先发窗口（【推断】）。风险提示：MCP 定位是 AI 集成协议而非实时控制协议，工业高危写操作必须叠加治理层——这正是 ADC 的 HITL 设计卡位点（【推断】）。

2. **IIoT 平台市场从"数据采集"向"预测与自治动作"迁移。**
   驱动力：全球 IIoT 平台市场 CAGR 12.8%（【事实】MnM TC 6664）；应用使能平台（Application Enablement）是增速最高的平台类别、资产管理是最大应用领域（【事实】同上）；预测性维护全球市场 2025 年 121.4 亿美元 → 2031 年 237.9 亿美元，CAGR 11.4%，制造业为最大终端行业（2026 年占 23.15%），亚太为增速最快区域（【事实】MnM TC 4154）。
   判断：传统 PdM 停留在"看板+告警"，客户下一阶段要的是"告警→诊断→受控处置"闭环，Agent 编排层恰好承接这一迁移（【推断】）。效益锚点：预测性维护可降低维护成本至多 30%、消除至多 70% 的突发故障（【事实】Accenture 研究，经 Wikipedia IIoT 词条引述）。

3. **LLM 推理成本持续下降，Agent 进入 OT 场景的经济性成立。**
   驱动力：2024-2026 年主流模型推理成本下降两个数量级（【推断】，基于公开价格战事实）。单次设备诊断/排产规划调用成本已低于一线工程师时薪的 1%（【猜测】）。这是 ADC 以 LLM 网关做 Token 计量、把 Agent 算力商品化的前提。

4. **中国制造业出海带动平台出海（东南亚近场优先、全球长线）。**
   驱动力：中国为全球最大机床生产国（2012 年产值 147 亿欧元、占全球 22%，【事实】Wikipedia 数控词条）；中国制造业对东南亚投资持续增长（【事实】贸易宏观背景）。判断：中资工厂出海后当地网络环境差、工程师短缺，NAT 反向穿透与远程 Agent 诊断的付费意愿反而强于国内（【推断】）。

5. **工业软件信创与数控系统国产化。**
   驱动力：华中数控等国产数控系统市占率提升（【事实】产业公开报道）。判断：设备软件栈的国产化替代将延伸至连接与编排层，为 Go 技术栈的国产创业团队提供大厂生态缝隙（【推断】）。

6. **原生 MCP 设备：设备厂商开始把 MCP Server 预置进设备，ADC 面向的"原生设备"正在出现。**
   驱动力与信号：消费与开发者侧先行——Home Assistant MCP（575 星）、mobile-mcp（5,913 星）、Android-MCP（810 星）等设备侧 MCP 项目已获社区验证（【事实】GitHub API 实测，引自竞品分析报告）；MCP 官方 SDK 覆盖 TypeScript/Python/C#/Java/Kotlin/Go/PHP/Perl/Ruby/Rust/Swift（【事实】Wikipedia MCP 词条），具备嵌入设备固件的工程条件。工业与机器人侧：本次调研未检索到设备厂商预装 MCP runtime 的公开公告（检索受限，见文末方法说明），但 OEM 以"AI 就绪"做产品差异化的动机明确（【推断】）。
   判断：设备侧 MCP 化将从"外挂盒子/适配器"走向"出厂预置 runtime"：智能家居与机器人厂商预计 2026-2027 年率先内置，工业设备（CNC/PLC/传感器）2027-2028 年起量（【推断】）。对 ADC 的含义：与设备商 OEM 合作预装 MCP runtime 的窗口与全球市场拓展窗口重合，"设备鉴权绑定 + 租户级虚拟 MCP 端点"正是原生 MCP 设备时代的治理底座（【推断】）。

7. **A2A 多 Agent 协作层市场形成中：设备编排价值从"单 Agent 调设备"升级为"多 Agent 协同调度设备"。**
   驱动力：Google 于 2025 年 4 月发布 A2A（Agent2Agent）协议，发布时 50+ 伙伴支持（Atlassian、SAP、Salesforce、ServiceNow、Workday 等）；2025 年 6 月捐给 Linux 基金会，当时已有 100+ 家企业宣布支持，微软、AWS、思科、SAP、Salesforce 相继加入（【事实】Google Developers Blog 2025-04-09、Linux Foundation 新闻稿 2025-06-23、Wikipedia A2A 词条）。A2A 与 MCP 分工明确：MCP 连接 Agent 与工具/数据，A2A 连接 Agent 与 Agent（【事实】Wikipedia A2A 词条）。
   判断：A2A 使 Agent 间任务委托标准化，"多 Agent 协同调度设备"（排产 Agent 委托诊断 Agent 调用 CNC 工具）成为可落地范式；企业将为"受控的多 Agent 设备协同"支付治理溢价，ADC 应把 A2A 协作层纳入产品范畴（【推断】）。风险提示：A2A 生态仍处早期，Wikipedia 词条存在来源可靠性存疑标注（【事实】），是否成为事实标准需按第 7 章假设 2 持续跟踪。

### 4.2 周期性与风险因素

- **制造业景气周期**：机加工行业受下游（汽车、3C、新能源）资本开支周期影响，设备改造预算 2025-2026 年偏紧（【推断】），可能延后但不会取消需求。
- **协议竞争风险**：MCP 与 OpenAPI 等集成协议的竞争仍在演化；A2A 与 MCP 为互补关系（MCP 连接 Agent 与工具，A2A 连接 Agent 与 Agent，【事实】Wikipedia A2A 词条），ADC 将同时保留 MCP 设备面与 A2A Agent 协作面的适配层；若工业界另立协议标准（如 OPC UA + AI 扩展），协议适配层需可插拔（【推断】）。
- **政策风险**：数据跨境（东南亚节点）、工业数据安全审查（等保 2.0、关基条例）会抬高合规成本（【事实】法规存在）。
- **伪需求风险**：客户说"需要 AI 排产"不等于愿意为 Agent 自主执行付费，详见第 7 章假设验证。

## 五、细分市场吸引力排序

评分 1-5 分（5 为最优），权重：规模 25%、增速 20%、竞争密度 20%、付费力 20%、进入难度 15%。

| 细分市场 | 规模 | 增速 | 竞争密度 | 付费力 | 进入难度 | 综合评级 |
|----------|------|------|----------|--------|----------|----------|
| 离散制造（CNC/PLC/机加工） | 5 | 4 | 3 | 4 | 4 | 4.0 |
| 高端消费电子制造（3C/半导体封测） | 4 | 5 | 3 | 5 | 4 | 4.0 |
| 物流仓储（AGV/AMR 协同） | 4 | 5 | 3 | 3 | 3 | 3.7 |
| 海外中资+欧美设备商（原生 MCP 设备） | 3 | 5 | 4 | 4 | 3 | 3.7 |
| 楼宇园区（暖通/能源管理） | 4 | 4 | 3 | 3 | 2 | 3.5 |
| 流程制造（化工/制药） | 4 | 3 | 5 | 5 | 5 | 3.3 |
| 能源（发电/电网） | 5 | 3 | 5 | 5 | 5 | 3.3 |

**排序理由：**
- **离散制造第一**：全球 IIoT 平台离散行业占 58.7%、增速最高（【事实】MnM TC 6664）；CNC/PLC 场景的"高危写操作必须人审"与 ADC 的 HITL 能力天然匹配；国内竞争集中在树根互联、徐工汉云等"数据平台"层，AI Agent 编排层尚是空白（【推断】）。
- **高端消费电子制造并列第一但后置**：付费力最强（头部代工厂 IT 预算充裕），但客户是富士康量级的强流程采购，小团队直接切入的销售周期与合规门槛过高（【推断】），宜作为第 2 阶段目标。
- **物流仓储**：增速快、AGV 协同与"柔性排产"场景相近，可复用设备编排内核（【推断】），列为第二扩张方向。
- **海外中资+欧美设备商（原生 MCP 设备）**：当前规模最小但增速预期最高——设备商预装 MCP runtime 的 OEM 渠道 2027-2028 年起量（【推断】）；竞争密度低（全球尚无带治理的工业 MCP 设备编排平台，【事实】见竞品分析报告）；付费方为设备商（AI 就绪差异化卖点）与海外中资工厂（跟随出海）；进入难度中等——依赖英文社区与 OEM 商务能力，无需先建海外直销团队（【推断】）。定位为双主场战略的海外一翼，与国内灯塔客户并行、第 3 年起主攻。
- **流程制造/能源**：规模大付费强，但西门子、Honeywell、Emerson 及国网系生态壁垒深、DCS 封闭（【事实】MnM 报告所列厂商格局），ADC 的 MCP 编排层在封闭系统内难落地，3 年内不建议投入。

## 六、市场进入策略

### 6.1 切入市场与切入场景

- **首发客户群：长三角/珠三角中型机加工与 3C 零部件工厂**（单厂设备 50-500 台 CNC，年营收 5000 万-10 亿元区间）。理由：设备密度高、停机损失可量化、决策链短（老板+设备主管即决策）、对"国产+便宜+见效快"敏感（【推断】）。
- **首发场景：预测性维护闭环（异常振动 → Agent 诊断 → 工单/受控处置）**。理由：价值可量化（停机 1 小时损失 500-2000 元，【估算假设】）、不需触碰产线控制逻辑（风险低）、与 ADC 现有技术方案（振动上报→诊断工具链→HITL）完全对应。
- **次发场景：设备台账问答与工艺知识助手**（低风险快速见效的"钩子产品"）。
- **不首发：柔性排产重构**——价值大但依赖全厂数据完备度与客户信任度，作为灯塔客户的第 2 个场景向上销售（【推断】）。
- **双主场基调**：中国市场以灯塔客户直销验证付费假设（本小节），海外市场自第 1 年起以开源社区英文优先运营并行启动（见 6.3），两条线共享同一产品底座与 i18n 基建；海外收入不进入中国 SOM 测算（【推断】）。

### 6.2 分阶段扩张路线

- **第 1 年（2026-2027）：单点验证。** 落地 5-10 个付费灯塔客户（企业版），500-1000 台设备在线；产品收敛到"边缘盒子（内嵌 MCP runtime）+ 云平台 + 企业微信/钉钉审批"一套标准交付；企业版按设备台数年订阅（社区版免费自部署）；所有高危工具调用默认走 HITL；产品 UI、文档与官网中英双语首发（i18n 自第 1 年起步）。里程碑：续费率 > 85%，单厂客单价 > 10 万元/年（【猜测】）。
- **第 2 年（2027-2028）：场景与客户升级。** 打入 1-2 家 3C/新能源零部件中大型客户（设备 1000+ 台）；上线柔性排产 Agent 场景；发展 3-5 家 SI/集成商渠道承担现场交付；补齐等保与 ISO 27001 认证。里程碑：ARR 800-1500 万元（【猜测】）。
- **第 3 年（2028-2029）：双主场——中国灯塔深耕 + 开源社区国际化并行。** 与 1-2 家国产数控系统厂商或机床厂（OEM）合作预装 MCP runtime，切入设备出厂即联网；海外主场走"开源国际化先行"（详见 6.3）：英文文档、英文社区与海外种子用户先于销售网络落地，中资客户跟随出海（优先已在国内付费的客户）作为并行路径；同步启动 A2A 多 Agent 编排适配与原生 MCP 设备 OEM 合作（接触欧美设备商）；开放设备工具契约生态（第三方 Agent 可接入）。里程碑：年收入 1500-3000 万元，其中海外占 10%-20%（【猜测】）。
- **i18n 里程碑（全栈国际化，英文+中文首发）：** 第 1 年产品 UI、文档、官网中英双语同步发布，社区以英文优先运营（英文为主、中文跟进）；第 2 年补齐企业版控制台、审批流与审计报告的多语言与多时区；第 3 年 i18n 覆盖全部交付物并具备海外区域部署合规能力（【推断】）。

### 6.3 开源漏斗：第一获客渠道

**渠道定位：** GTM 主渠道为"开源社区漏斗优先"——GitHub 开源获客 → 自助部署 → 企业版转化，OEM/集成商渠道与灯塔案例并行（【推断】）。开源同时承担出海门票职能：海外工程师与工厂 IT 通过开源评估产品，海外销售无需从零建立信任（【推断】）。

**分阶段设计：**

- **第 1 年（2026-2027）：开源发布与种子社区。** 里程碑：核心仓库 Apache-2.0 开源（边缘 runtime + 云平台 + HITL 审批链路），配套中英双语文档与一键部署（Docker Compose）；目标 GitHub star 2,000-5,000、镜像下载 1 万-3 万次、自部署活跃实例 200-500 个（【猜测】，参照国内工业开源项目社区量级）。开源流量主要转化为注册与销售线索，付费仍来自 6.2 灯塔客户。
- **第 2 年（2027-2028）：社区到企业版的转化机制化。** 社区版固定为"设备编排 + 单租户 + 基础 HITL"，企业版承载多租户、HITL 合规审计、预测性维护 Agent、SSO/审计日志等，支持企业版 SaaS 订阅与私有化（买断+年费）两种交付；建立"社区注册 → 销售线索 → 企业版订阅"自动化转化链路与销售协同（PLG 与销售协同并存）；目标社区注册用户 5,000-10,000、注册→线索转化 5%-10%、线索→付费 10%-20%（【猜测】）。
- **第 3 年（2028-2029）：开源国际化先行（海外主场核心渠道）。** README、文档、官网、Issue 全英文维护（社区英文优先运营），英文技术内容（博客/上手视频）与中文同步发布；以全球开发者与东南亚本地工程师为核心种子用户，海外企业版授权由本地 OEM/集成商承接交付（【推断】）。中资客户跟随出海为并行路径（6.2）。

**对海外扩张的加速作用：** 传统路径需先建海外销售团队再触达客户，周期长、成本高；开源先行可在第 2 年即积累海外开发者与安装基础，第 3 年海外企业版转化建立在已有信任之上，预计压缩出海周期 1-2 年（【推断】）。

**开源战略的风险与取舍：** 开源核心可能被竞对（含大厂）复用，需接受；护城河在企业版治理能力（HITL 合规审计、工业协议适配矩阵、行业认证），而非连接协议本身（【推断】）。

### 6.4 进入门槛与所需资源

- **OT 现场交付能力**：CNC/PLC 协议适配（Fanuc、西门子、华中数控等）是最大工程投入，小团队前期可外包给 SI，但核心 2-3 类协议必须自研（【推断】）。
- **信任资产**：工业安全资质（第 2 年补齐）、灯塔案例、HITL 审批链路可审计（满足客户安全部门审查）。
- **人才**：Go 后端 + 1 名懂机床工艺/设备运维的行业顾问（兼职亦可）+ 1 名销售（来自设备行业或 MES 厂商）+ 1 名开发者关系/社区运营（具备英文内容能力，第 1 年兼职、第 2 年起全时，【推断】）。
- **预算**：12-18 个月内需要 300-500 万元（团队 8-12 人 + 硬件样机 + 销售差旅，【估算假设】）。

## 七、关键假设与验证方案

| 假设 | 重要性 | 证伪手段 | 成本 |
|------|--------|----------|------|
| 1. 中型工厂愿意为企业版设备编排+Agent 协同支付约 1000 元/台/年的订阅（社区版免费只引流、不产生收入） | 高（决定 SAM 是否成立） | 6 个月内对 20 家目标工厂做付费意愿访谈；对 5 家做付费试点（预付 3 个月）；低于 3 家付费即证伪 | 约 5 万元/月 |
| 2. MCP 在工业设备侧的采纳会持续加速，无强替代协议出现 | 高（决定技术路线存亡） | 每季度跟踪 AAIF/MCP 官方生态、机床厂与工控厂商的 MCP 公告；同时保持协议适配层可插拔 | 0（跟踪成本） |

| 4. 预测性维护场景单厂价值可量化（停机损失、备件库存下降） | 中（决定续费与增购） | 灯塔客户上线 90 天做 A/B 对照：故障提前预警次数 × 单次停机损失 | 0（产品内埋点） |
| 5. 中国数控机床保有量约 600 万台、可联网高价值设备占比 25%-35% | 中（影响 SAM 上限） | 采购/申请 Gardner Intelligence 或中国机床工具工业协会年鉴数据复核 | 1-2 万元 |
| 6. 客户接受 HITL 审批流程（5 分钟级时延）而非反感"AI 要人批" | 中（影响产品形态） | 试点期统计审批响应时延、拒绝率、客户工程师主观评价；拒绝率 < 5% 且时延中位数 < 3 分钟为达标 | 0（产品内统计） |
| 7. 开源下载→部署转化率约 20%（每 100 次下载产生约 20 个自部署实例，【估算假设】） | 中（决定开源漏斗顶部效率与社区投入规模） | 边缘 runtime 与云平台内置匿名安装统计；开源发布后连续 3 个月实际转化率低于 10% 且无上行趋势，则重做一键部署与上手文档后再评估 | 约 1 万元/月（埋点与文档迭代） |
| 8. 开源部署→企业版付费转化 3%-5%、社区注册→销售线索转化 5%-10%（全部【估算假设】） | 中高（决定开源主渠道整体是否成立，直接影响 CAC 与渠道预算分配） | 按月统计部署实例→企业版咨询→付费漏斗与注册→线索转化；连续 3 个月部署→付费低于 1%，则回退为销售驱动，压缩开源投入并转向 OEM/集成商渠道 | 约 2 万元/月（埋点与社区运营） |
| 9. 原生 MCP 设备规模化时间：智能家居/机器人厂商 2026-2027 年内置 MCP、工业设备 2027-2028 年起量（【推断】） | 高（决定 OEM 渠道节奏与海外主场的启动时点） | 每季度跟踪设备厂商 MCP 预装公告（CES/MWC/工博会发布、厂商开发者文档、AAIF 生态名单与 GitHub 设备 MCP 项目增速）；若 2027 年底仍无 5 家以上设备厂商公开预置 MCP，则将 OEM 渠道押后一年、加大外挂盒子路线投入 | 0（跟踪成本） |

**验证优先级：假设 1 是生死假设，应在任何大规模研发投入前先行证伪。** 假设 7/8 决定开源主渠道是否成立，应在开源发布后 3-6 个月内用漏斗数据验证并决定开源预算去留；假设 9 决定 OEM 与海外主场的启动时点，以零成本季度跟踪持续观察；假设 2 决定 3 年后的天花板，假设 3/4/6 决定交付效率，假设 5 只需买数据即可关闭。
