## 1. 测试目标与范围

### 1.1 测试目标

1. 验证 V1.0 范围内全部功能需求（FR-001 至 FR-010、FR-013、FR-014、FR-018 至 FR-020）的验收标准逐条可判定、可执行，证据留存测试报告与自动化运行记录。
2. 验证 SEC-01 至 SEC-14 全部安全发现修复有效，通过攻击视角用例（重放、篡改、伪造回调、跨租户越权）证明信任边界恢复设防。
3. 验证非功能指标（NFR-001/003/004/006）达成发布门禁：免审指令 P95 不超过 500ms、HITL 拦截率 100%、免审任务成功率不低于 99%、审计留存 180 天。
4. 为发布决策提供三项客观数据：用例通过率、阻断级缺陷数、性能基线，缺一不放行。
5. 验证统一 API 网关契约稳定性：前端唯一入口下，后端服务（Go 数据面 / Python Agent 面）实现变更不破坏前端契约（前端无感后端语言切换，GW-008/XL-005）。

### 1.2 在测范围

- 功能面：FR-001 设备反向接入隧道（WSS）、FR-002 设备鉴权（Token/HMAC/mTLS）、FR-003 工具动态发现与聚合、FR-004 集群化工具路由、FR-005 HITL 高危指令审批、FR-006 工具风险等级配置、FR-007 审批流策略配置、FR-008 租户与组织管理、FR-009 Agent API Key 管理、FR-010 设备纳管与生命周期、FR-013 审计日志查询与导出、FR-014 管理控制台、FR-018 开源工程化、FR-019 企业功能开关与版本切分、FR-020 开源文档站与示例工程。
- 非功能面：NFR-001（可用性，测试期以故障演练验证 RPO/RTO）、NFR-003（时延五项指标）、NFR-004（安全，见第 7 节）、NFR-006（日志留存与可观测）。NFR-002 按共享基线执行：V1.0 以单节点 1000 台在线设备为验证门槛。
- 平台工程面：统一 API 网关（Go，前端唯一入口）契约与路由；Python Agent 面（FastAPI）V1.0 最小集——评测工具链与开发脚本；Python 面完整能力（LLM 网关 FR-012、A2A FR-022）属 V1.5，本版本仅验证网关预留端点联通性（XL-004）。
- 安全面：SEC-01 至 SEC-14 逐项验证（见第 7 节），另含开源发布相关扫描（SEC-25 延伸项、许可证扫描、密钥扫描）。
- 发布门禁专项：审计留存 180 天验证（数据构造 + 时间边界查询 + 追加完整性校验）。

### 1.3 不在测范围（V1.5 及以后功能不测）

- FR-011 设备批量纳管与分组、FR-012 LLM 网关、FR-015 边缘 SDK 包分发、FR-016 计量计费、FR-017 系统健康监控与告警、FR-021 原生 MCP 设备鉴权绑定、FR-022 A2A Agent Card、FR-023 全栈 i18n、FR-024 内部多 Agent 编排引擎。
- NFR-002 的 1 万在线设备压测（V1.5 门禁）、NFR-005 等保 2.0 三级测评（V1.5 门禁）。
- 生产环境客户 UAT 与 2 家种子工厂试点运行（属试点验收，不在本计划执行范围，但其 4 周无 P0/P1 缺陷结论依赖本计划的功能回归数据）。

## 2. 测试策略与分层

### 2.1 测试金字塔与投入占比

按风险分配投入，高危链路（设备鉴权、HITL 审批、租户隔离、审计）在任何层级都优先于展示类界面。

| 层级 | 目标 | 占比（预估） | 主要手段 |
|------|------|-------------|---------|
| 单元测试 | 纯函数与状态机逻辑：HMAC 签名、风险判定、工单状态机、配额计算、Key 哈希（Go 侧与 Python 侧各自覆盖） | 约 55% | go test（表驱动）、Vitest、pytest |
| Python Agent 面测试 | 评测工具链 CLI、评测报告生成、FastAPI 路由与中间件、失败场景（V1.0 最小集） | 约 8% | pytest + pytest-asyncio + httpx/TestClient |
| 集成测试 | 组件间契约：网关与 PostgreSQL/Valkey、跨节点路由、回调验签与工单消费 | 约 15% | testcontainers-go、契约测试 |
| 网关集成与契约 | 统一网关前缀路由、鉴权头透传、trace_id 贯通、限流头、错误归一、后端替换无感 | 约 7% | OpenAPI 契约校验自动化、golang httptest |
| 端到端测试 | 用户视角全链路（经网关发起）：设备接入、工具调用、审批、审计查询 | 约 10% | Playwright（控制台）+ 自研设备模拟器 |
| 专项测试 | 性能、安全、兼容、故障注入 | 约 5% | k6、go-race、govulncheck、浏览器矩阵 |

### 2.2 各层工具选型与执行时机

| 层级 | 工具 | 说明 |
|------|------|------|
| Go 单元测试 | go test（表驱动 + 子测试）+ testify 断言 + go-race | 表驱动覆盖等价类与边界值；数据面服务强制 -race 运行，捕获 HITL 并发竞态（对应 SEC-11 修复验证） |
| 前端单元测试 | Vitest + Vue Test Utils | 控制台组件与 Pinia store；覆盖租户数据过滤、菜单裁剪、审批工单列表刷新 |
| 集成测试 | testcontainers-go 拉起真实 PostgreSQL 16 与 Valkey 7.2 | 禁止 mock 数据库层；仅外部 HTTP 依赖（企微/钉钉/LLM）使用 Mock 服务器；集成测试验证 SQL、锁、TTL 真实行为 |
| E2E | Playwright（Chromium 起步）+ 自研 Go 设备模拟器 | 模拟器支持脚本化工具集、断连、重连、篡改报文注入 |
| 性能 | k6 压统一网关（前端唯一入口，含 Agent 面路由）；自研 Go 压测脚本压设备 WSS 面 | 设备面无现成 k6 WebSocket 大规模连接模板，采用自研连接池脚本，指标经 Prometheus 采集 |
| 安全 | govulncheck（依赖漏洞）、gitleaks（密钥扫描）、licensecheck + SBOM 生成（开源门禁，FR-018）、Nuclei（基础 Web 探测）、手工渗透清单（第 7 节） | 与 CI 门禁并列执行 |
| 竞态检测 | go test -race + 双实例并发场景脚本 | HITL 双判、同设备双连（SEC-15）必须过 race |
| Python Agent 面测试 | pytest + pytest-asyncio + httpx/TestClient | 评测工具链 CLI 用 pytest 子进程级用例；FastAPI 服务用 TestClient（ASGI 进程内）或 uvicorn 起真实服务；异步场景由 pytest-asyncio 驱动 |
| Python 静态与类型检查 | ruff（lint/format）+ mypy（严格模式） | 与 CI 门禁并列执行，作为 Python 面质量门禁（对应 PY-007） |
| 网关契约测试 | OpenAPI 契约校验自动化 | 网关对外契约与其声明 OpenAPI 文档逐接口比对（方法、路径、参数、响应码、错误码 10001 等）；后端服务任一实现变更必须重跑，契约不变即前端无感 |

执行时机：单元与集成测试在本地提交前与 CI 每次合并运行；网关契约测试在 CI 每次合并运行（后端任一服务变更必须重跑）；E2E 冒烟集在 CI 每日运行、全量集在迭代末回归运行；性能与安全专项在发布候选阶段运行。

## 3. 测试环境

### 3.1 环境清单

| 环境 | 用途 | 形态 | 数据 |
|------|------|------|------|
| 本地开发环境 | 开发自测、单测、集成测试 | Docker Compose 起 PostgreSQL 16 + Valkey 7.2 + Mock 服务器 | 构造数据，任意重置 |
| Python 服务测试环境 | 评测工具链与 Python Agent 面（FastAPI）开发自测、单测与集成 | 本机 venv 隔离，依赖由 uv 按 uv.lock 固化管理；FastAPI TestClient（进程内）或 uvicorn 起真实服务连测试库 | 构造数据，任意重置 |
| CI 环境 | 门禁流水线：单测、race、集成、网关契约、E2E 冒烟、许可证与密钥扫描 | 每个 PR 起全新容器组，测试后销毁；Go 与 Python 双语言矩阵并行执行（见 3.5） | 种子数据，无敏感信息 |
| 预发环境（Staging） | 全量回归、性能基线、故障演练、180 天留存验证 | 与生产同构部署（Compose 单机 + 双实例集群两套拓扑） | 脱敏构造数据 + 时间回拨构造 |
| 生产环境 | 上线后冒烟与拨测（不含压测） | 正式部署 | 真实数据，仅读为主 |

### 3.2 依赖编排（Docker Compose）

基础编排文件维护于仓库 `deploy/test/`：

- `postgres:16`：挂载初始化 SQL（schema + 分区表 + 种子数据），开启慢查询日志（超过 500ms 记录），供审计查询性能用例取证。
- `valkey:7.2`：开启 ACL（按节点账号最小权限，对应 SEC-06 验证场景），配置 `appendonly yes` 供重启持久化用例。
- `mock-webhook`：自研 Mock 服务器，模拟企业微信与钉钉 webhook 接收、卡片回调签发与推送延迟/失败注入（见 3.4）。
- `adc-agent-py`（Python Agent 面，FastAPI）：V1.0 最小集含评测工具链与开发脚本服务；镜像多阶段构建 + 非 root 运行，依赖经 uv 锁定（uv.lock）；V1.5 起承接 LLM 网关与 A2A。
- `adc-api-gateway`（统一 API 网关，Go）：前端唯一入口，按 OpenAPI 契约路由至数据面与 Python Agent 面，统一处理鉴权头透传、trace_id 贯通、限流头与错误码归一（对应 GW 用例组）。
- `adc-gateway`（数据面）与 `adc-admin`（控制面）：被测服务镜像，按 ADR-01 控制面/数据面拆分部署；集成测试与 E2E 各自起独立组。
- 双实例拓扑文件 `deploy/test/compose.dual.yml`：两个数据面实例共享 PostgreSQL/Valkey，专用于 SEC-10 跨节点唤醒、SEC-11 并发审批、FR-004 跨节点路由用例。

### 3.3 数据构造与脱敏

- 构造器：Go 测试库 `testdata/` 提供工厂函数，按租户模板生成设备（含三种鉴权方式）、工具（覆盖风险等级 0-3）、API Key、审批人与组织角色。
- 时间构造：审计 180 天留存验证采用"时间回拨"策略——预发环境写入带历史 `event_time` 的审计数据（180 天前、179 天、1 天、当前），验证查询窗口与保留策略；不真实等待 180 天。
- 脱敏：所有测试数据使用虚构设备码（`TEST-` 前缀）、虚构工号、无真实手机号；Mock 回调身份取测试用 OAuth 假令牌；严禁将生产数据导入测试环境，如需联调必须经脱敏管道（替换设备码、租户名、参数值）。

### 3.4 Mock 策略

| 外部依赖 | Mock 方式 | 可注入故障 |
|---------|----------|-----------|
| 企业微信/钉钉 webhook | mock-webhook 服务器（同一服务双端点） | 返回 5xx（验证 SEC-18 重试与告警）、延迟超过 30 秒（验证卡片送达告警）、超时无响应 |
| IM OAuth 回调签发 | mock-webhook 按测试配置签发/拒签 HMAC 签名 | 篡改签名、过期时间戳、错误 approver（验证 SEC-01） |
| LLM 供应商 | 本计划范围外（FR-012 为 V1.5），仅 Agent 侧模拟器直接发起 tools/call，不经 LLM | 无 |
| 真实 IM 沙箱 | 端到端最终验收阶段，与企微/钉钉测试应用各做一轮真实推送冒烟 | 仅联调用，不进自动化 |

### 3.5 CI 双语言矩阵

- Go 侧：golangci-lint + go test（含 -race），与现有门禁一致；Python 侧：ruff check + mypy（严格模式）+ pytest（异步用例由 pytest-asyncio 驱动），依赖由 uv 按 uv.lock 固化安装（--frozen），任一静态检查失败即阻断 PR。
- 矩阵组合：Go 版本 × Python 版本各取当前稳定档组成组合，任一组合失败均阻断；单元与静态检查并行执行，网关契约测试与跨语言集成用例在合并后统一执行。
- Python 侧质量门禁与 Go 侧同等权重，保证双语言基线一致；本地 Python 服务测试环境与 CI 使用同一 uv.lock，杜绝"本机过、CI 挂"。

### 4.2 重点模块用例大纲

#### 4.2.1 设备鉴权（FR-002，SEC-03/05/04 交叉）

- AUTH-001 有效 Token 建立隧道成功（前置：FR-010 已注册设备）。
- AUTH-002 无效 Token 返回 403，记录鉴权失败审计事件。
- AUTH-003 HMAC 重放攻击：捕获合法请求后原样重发，服务端拒绝（nonce 已消费）。
- AUTH-004 HMAC 篡改：修改 timestamp 或 body 任一字段，签名校验失败返回 403。
- AUTH-005 HMAC 时间窗：timestamp 漂移超过 5 分钟窗口，拒绝；窗口内合法放行。
- AUTH-006 凭证吊销后旧连接被踢下线，重连返回 403（关联 FR-010）。
- AUTH-007 mTLS：证书不在白名单拒绝 TLS 握手；已吊销证书拒绝握手。
- AUTH-008 切换鉴权方式（Token 改 HMAC）需二次确认，审计记录变更。
- AUTH-009 伪造成"另一个租户设备码 + 自己凭证"组合被拒（凭证与设备码强绑定）。
- AUTH-010 非法 Origin 的 WebSocket 升级请求被拒（SEC-04）。

#### 4.2.2 HITL 审批（FR-005/007，SEC-01/08/10/11/13/18 交叉）

- HITL-001 等级 2 工具调用被拦截，生成 Ticket UUID，30 秒内卡片推送成功（Mock webhook 收到）。
- HITL-002 审批人同意：回调签名合法、工单未处理，指令下发执行，Agent 收到执行结果；审计含真实 approver 工号。
- HITL-003 审批人拒绝：指令不执行，Agent 收到 BLOCKED_BY_HITL。
- HITL-004 工单超时（默认 5 分钟）：到期未处理，自动终结，Agent 收到 BLOCKED_BY_HITL。
- HITL-005 无签名回调返回 401（SEC-01）。
- HITL-006 篡改签名回调（改 ticket_id、decision 或时间戳）被拒并记录异常事件（SEC-01/13）。
- HITL-007 伪造 approver：回调身份不属于该工单审批人列表，拒绝（SEC-01）。
- HITL-008 并发双判：两个合法回调并发提交 approve 与 reject，状态机原子更新，仅一个生效（SEC-11，配合 -race 运行）。
- HITL-009 过期工单回调：超过 ExpireAt 后 approve 被拒（SEC-11）。
- HITL-010 已处理工单重复回调：返回"已处理"，不重复下发指令。
- HITL-011 审批中设备离线：工单自动失效，Agent 收到错误并注明原因。
- HITL-012 卡片推送失败：重试 3 次（指数退避），仍失败则告警且工单最终超时收敛（SEC-18）。
- HITL-013 跨节点唤醒：双实例部署，Agent 在节点 A 挂起、审批回调落在节点 B，秒级唤醒并回传结果（SEC-10）。
- HITL-014 重启恢复：工单持久化于 PostgreSQL，网关重启后工单仍可查询、可继续处理（SEC-08）。
- HITL-015 两级审批：一级同意后推送二级，全部同意才执行；任一级拒绝即终止（FR-007）。
- HITL-016 免审白名单：工具 + 参数范围 + 时间段全部命中时直接执行，审计记录免审依据；任一条件不命中仍拦截（FR-007）。
- HITL-017 一级超时升级：按策略升级至上级或自动拒绝（FR-007）。
- HITL-018 策略变更不影响在途工单，仅对新工单生效（FR-007）。

#### 4.2.3 租户隔离（FR-008，SEC-02/20 交叉，跨租户 403 用例集）

- TEN-001 租户 A 设备仅租户 A Agent 可见；租户 B 的 tools/list 不含租户 A 工具（FR-003 聚合视图隔离）。
- TEN-002 租户 A 的 API Key 携带请求头伪称租户 B，返回 403（租户上下文取自凭证而非请求头，SEC-02）。
- TEN-003 租户 A 管理员 API 查询租户 B 设备/审计/工单，全部返回 403。
- TEN-004 租户 A 的审批回调绑定租户 B 工单 ticket_id，被拒（工单校验绑定租户）。
- TEN-005 Valkey 键空间验证：伪造 `tenant:B:device:xxx` 路由键无法由租户 A 上下文写入；设备 ID 含非法字符被拒（SEC-20）。
- TEN-006 配额超限：超过设备数或调用量配额，返回明确配额错误码。
- TEN-007 租户停用：其设备连接被踢下线、在途审批工单全部失效、新调用拒绝。
- TEN-008 租户删除进入 7 天冷静期，冷静期内可恢复；删除后数据隔离保留策略验证。
- TEN-009 未带凭证或伪造凭证访问 Agent 端点，返回 401（SEC-02）。

#### 4.2.4 审计（FR-013，SEC-07/21 交叉）

- AUD-001 任意工具调用完成后，3 秒内可按 tenant_id + trace_id 查询到审计记录（SEC-07）。
- AUD-002 审计字段完整性：tenant_id、agent_id（真实值非硬编码，SEC-21）、device_id、tool、status、hitl_approver、参数与响应。
- AUD-003 审批决策留痕：approve/reject/超时三类决策均落库，含审批人真实身份与审批意见。
- AUD-004 append-only 验证：尝试经 API/直接 SQL 修改或删除审计记录，一律失败；数据库层以只读账号与触发器双重保障。
- AUD-005 组合条件查询（时间 + 租户 + 设备 + 工具 + 状态）3 秒内返回，分页完整。
- AUD-006 导出 CSV 与 JSON 各一次，字段与在线查询一致；导出超过 10 万条自动转异步任务。
- AUD-007 响应负载超过阈值截断并标注（不破坏 JSON 结构）。
- AUD-008 180 天留存：历史数据可查、180 天前数据按保留策略处理的行为符合设计（构造数据验证，见 3.3）。
- AUD-009 免审调用记录免审依据字段（关联 FR-007）。

#### 4.2.5 API Key（FR-009）

- KEY-001 创建后完整 Key 仅显示一次，数据库仅存哈希（直接查询表验证）。
- KEY-002 权限范围：调用范围外工具返回 403 并记录审计。
- KEY-003 已吊销 Key 返回 401；过期 Key 返回 401。
- KEY-004 审计日志包含 key_id 与 agent_id 字段。
- KEY-005 单 Key 1 分钟内 100 次失败触发熔断告警（阈值可配，测试时调低阈值注入）。
- KEY-006 轮换：新旧 Key 并行 24 小时过渡，过渡期后旧 Key 自动失效。
- KEY-007 Key 哈希比对使用恒定时间比较（代码评审 + 单测验证，防时序侧信道）。

#### 4.2.6 风险等级（FR-006，SEC-09 交叉）

- RISK-001 工具名为 stop 但等级配置为 0，直接执行不触发 HITL（证明无关键字硬编码残留，SEC-09）。
- RISK-002 改名绕过验证：将 set_spindle_speed 改名为 set_rpm，等级 2 仍被拦截（SEC-09）。
- RISK-003 控制台修改等级后 30 秒内网关拦截行为生效。
- RISK-004 未配置等级的工具按租户默认策略（默认等级 2）分配。
- RISK-005 等级下调（2 降 0）需二次确认并写入审计。
- RISK-006 设备离线重连后，等级以平台配置为准（不被设备侧旧值覆盖）。

#### 4.2.7 隧道与路由（FR-001/004，SEC-14/15 交叉）

- TUN-001 隧道建立后 5 秒内完成 tools/list 同步。
- TUN-002 断线重连：指数退避（1 秒起步、上限 60 秒），重连成功重新注册工具。
- TUN-003 60 秒未收 Pong 判定离线，清理本地会话与 Valkey 路由，状态置 offline。
- TUN-004 单条消息超过 512KB 拒绝并断开连接，记录告警日志。
- TUN-005 同设备二次连接：旧会话被主动关闭且不误删新会话（SEC-15）；断旧连后新连仍可路由。
- TUN-006 长连接存活 1 小时仍可路由（TTL 续期，SEC-14）。
- TUN-007 跨节点调用：设备连节点 B，节点 A 收到 tools/call，经 Valkey Pub/Sub 转发并回传（FR-004）。
- TUN-008 节点宕机后其管理设备 90 秒内被清理。
- TUN-009 Pub/Sub 投递超时 15 秒返回超时错误；主从切换期间自动重试一次。

#### 4.2.8 网关契约与路由（统一 API 网关，前端唯一入口）

- GW-001 前缀路由正确性：`/v1/agent/` 前缀请求路由至 Python Agent 面，`/v1/devices/` 与 `/v1/admin/` 前缀路由至数据面/控制面；各后端仅收到属于自己前缀的请求。
- GW-002 未命中路由：未知路径与未知前缀返回 404，响应体为统一业务错误码 10001，符合网关 OpenAPI 错误契约。
- GW-003 鉴权头透传：前端携带的 Authorization、租户与请求头经网关原样透传至后端，后端校验通过；网关不解析、不落盘、不改写凭据内容。
- GW-004 trace_id 贯通：网关生成或透传 trace_id，请求链路（网关 → 数据面 / Python Agent 面 → 审计）日志与审计记录中 trace_id 一致，可按其串联（NFR-006）。
- GW-005 限流响应头：限流命中返回 429 并携带 Retry-After；未命中时按契约返回限流余量信息头（SEC-12）。
- GW-006 错误归一：后端超时或返回内部错误时，网关按契约转为统一网关错误码与结构化错误体，不透出后端内部堆栈与路径。
- GW-007 后端宕机降级：数据面服务宕机时，网关对设备与调用路由返回 502 并记录告警；服务恢复后无需重启网关即恢复路由（NFR-001 故障演练）。
- GW-008 后端替换无感：`/v1/agent/` 后端在 Go 实现与 Python 实现间切换，OpenAPI 契约校验通过且前端 E2E 必跑集全绿，前端无感后端语言切换。
- GW-009 OpenAPI 契约一致性：网关对外契约与其声明 OpenAPI 文档逐接口比对（方法、路径参数、响应码、错误码 10001 等），自动化校验通过。
- GW-010 鉴权决策不下沉缓存：后端凭证吊销后，经网关的新请求立即返回 401/403，网关不缓存鉴权结果（凭证校验以各后端为准）。

#### 4.2.9 Python Agent 面（FastAPI，V1.0 最小集：评测工具链与开发脚本）

- PY-001 评测 CLI 正常执行：输入合法评测配置（JSON）与样本集，CLI 退出码 0，输出结构化结果（通过率、失败明细）。
- PY-002 评测 CLI 输入校验：配置缺必填字段或格式非法，CLI 退出码非 0，错误信息可读且符合错误码表（不抛裸堆栈）。
- PY-003 评测报告生成：评测完成后生成 JSON 与 Markdown 报告，字段完整（用例数、通过率、失败明细、耗时）。
- PY-004 评测失败场景：样本执行超时或断言失败，单条用例标记失败但不中断整体评测，报告含失败原因与耗时。
- PY-005 开发脚本幂等：脚本重复执行结果一致，无副作用残留（临时文件、缓存清理完整）。
- PY-006 FastAPI 服务契约基线：`/healthz` 与预留 Agent 端点返回符合统一错误契约；服务在 TestClient 与 uvicorn 真实服务两种形态下行为一致（V1.5 全量扩展的基线）。
- PY-007 Python 面静态门禁：ruff 零错误、mypy 严格模式通过，纳入 CI 作为质量门禁（与 2.2 表一致）。

#### 4.2.10 跨语言集成（Go 数据面 ↔ Python Agent 面）

- XL-001 评测任务跨语言闭环：Go 数据面经内部 API 调用 Python 面评测工具链服务创建任务并回传结果，结果与 Python 侧直跑一致。
- XL-002 跨语言鉴权透传：网关 → Python 面的调用携带有效凭证放行，无凭证的内部调用被拒（SEC-02 延伸至 Python 面）。
- XL-003 trace_id 跨语言贯通：Go 面调用 Python 面携带同一 trace_id，两侧日志与审计可串链（NFR-006 延伸）。
- XL-004 A2A 预留端点联通性（V1.5）：网关 `/v1/a2a/` 前缀路由至 Python 面预留端点，健康探测与空路由返回符合契约；完整 A2A 功能用例归 V1.5（FR-022 不在 V1.0 范围）。
- XL-005 前端无感切换端到端验证：同一前端 E2E 必跑集在"Agent 面 Go 实现"与"Agent 面 Python 实现"两种后端下各跑一遍，通过率一致（GW-008 的端到端侧验证）。

### 4.3 等价类与边界值要点

- 消息大小：512KB 边界三值（511KB 放行、512KB 拒绝、513KB 拒绝，FR-001）。
- 心跳超时：59 秒在线、60 秒判定离线（FR-001）。
- HMAC 漂移窗口：4 分 59 秒放行、5 分钟边界、5 分 1 秒拒绝（FR-002）。
- 风险等级取值：0/1/2/3 四个有效类、-1 与 4 两个无效类、缺省类（FR-006）。
- 审批超时：4 分 59 秒同意生效、5 分钟到期拒绝（FR-005）。
- 免审时间段：起止边界（整点前后 1 秒）与参数范围上下界（FR-007）。
- 配额：等于配额放行、配额 +1 拒绝（FR-008）。
- 审计导出：99999 条同步、10 万条转异步（FR-013）。
- 工单并发：双回调同毫秒级并发（SEC-11）；工具聚合可见性 29/30/31 秒三值（FR-003）。
- 设备码格式：白名单字符集与长度上限（SEC-20），含 `__` 的设备码不破坏路由（SEC-24）。

## 5. 关键场景端到端用例

以下 9 条为 V1.0 主链路验收用例，全部自动化，作为每次发布前的必跑集。全部用例经统一 API 网关发起请求（前端唯一入口，前端无感后端语言切换）。

**E2E-01 设备接入与工具发现（FR-001/002/003）**
- Given：管理员已在控制台注册设备并签发 Token，Mock 设备模拟器就绪。
- When：模拟器携带 Token 发起 /v1/devices/tunnel 升级请求并上报 3 个工具。
- Then：隧道建立；5 秒内完成 tools/list 同步；30 秒内 Agent 经 /v1/agent/mcp/tools/list 查询到 3 个"设备码__工具名"工具；设备台账状态为 online；审计含 device_connected 事件。

**E2E-02 低危工具免审直调（FR-003/004/006，NFR-003）**
- Given：E2E-01 状态就绪，其中工具 A 等级配置为 0。
- When：Agent 携带有效 API Key 调用工具 A（租户 A 上下文）。
- Then：不生成审批工单；指令经路由下发至设备执行；Agent 收到结果；审计记录含 tenant_id、agent_id、device_id、tool、status=success；端到端时延记录用于成功率与 P95 统计。

**E2E-03 高危调用触发 HITL 与同意执行（FR-005/006，G3）**
- Given：工具 B 等级为 2，Mock 审批人已配置。
- When：Agent 调用工具 B。
- Then：指令不执行；生成 Ticket；30 秒内 Mock webhook 收到卡片；审计记录 hitl_intercepted；审批人点击同意且回调签名合法后指令下发执行；Agent 收到执行结果；审计含真实 approver 与审批意见。

**E2E-04 高危调用拒绝与超时（FR-005）**
- Given：同 E2E-03 前置，分别执行两次调用。
- When：第一次审批人点击拒绝；第二次不作任何操作等待超时。
- Then：两条指令均不执行；Agent 均收到 BLOCKED_BY_HITL；工单状态分别为 rejected 与 timeout；审计留痕完整。

**E2E-05 跨节点路由与跨节点审批唤醒（FR-004，SEC-10）**
- Given：双实例部署，设备连接在节点 B，Agent 请求落在节点 A。
- When：Agent 经节点 A 调用等级 2 工具，审批回调提交至节点 B。
- Then：调用经 Valkey Pub/Sub 转发至节点 B 的审批挂起点，秒级唤醒；同意后指令下发、结果回传节点 A；全程无 5 分钟超时等待。

**E2E-06 审批期间设备离线（FR-005 异常场景）**
- Given：E2E-03 状态就绪且工单处于待审批。
- When：模拟器模拟设备断线（网络闪断且不重连）。
- Then：工单自动失效；Agent 收到错误并注明设备离线；审批人稍后点击同意被拒（工单已失效）；审计记录完整因果链。

**E2E-07 审计查询与导出闭环（FR-013/014，NFR-006）**
- Given：E2E-01 至 E2E-06 已执行产生完整审计数据。
- When：审计员登录控制台，按"时间 + 租户 + 工具 B + 状态"组合条件查询并点击导出 CSV。
- Then：3 秒内返回结果且分页完整；导出文件包含调用参数、响应、审批人与审批意见字段；尝试修改任一审计记录失败（append-only）；trace_id 可贯通接入、调用、工单三条记录。

**E2E-08 设备凭证吊销联动（FR-002/010）**
- Given：设备在线且工具已聚合。
- When：管理员在控制台吊销该设备凭证并填写操作理由。
- Then：现有连接被踢下线；工具从聚合中摘除；重连返回 403；台账历史日志仍可查询；吊销操作与理由计入审计。

**E2E-09 租户隔离端到端（FR-008，SEC-02）**
- Given：租户 A 与租户 B 各有 1 台设备、1 个 Agent Key。
- When：租户 B 的 Agent 携带请求头伪称租户 A 调用工具；租户 A 管理员查询租户 B 设备与审计。
- Then：调用返回 403；查询返回 403；双方 tools/list 互不可见；审计记录保留全部越权尝试。

### 6.2 场景设计

| 场景 | 脚本 | 加压方式 | 判定 |
|------|------|---------|------|
| 设备连接容量 | 自研 Go 连接池脚本 | 1000 台模拟设备阶梯加压（10 分钟升满），保持 1 小时 | 连接全部稳定、心跳零丢失、内存与 CPU 无泄漏趋势、tools/list P95 达标 |

| 限流验证（SEC-12） | k6 超限请求 | 单 Agent 超过阈值请求 | 返回 429，网关正常服务其他租户 |
| 重连风暴 | 自研脚本 1000 台同时断线重连 | 瞬时 1000 并发重连（指数退避生效前） | 网关存活、无连接队列雪崩、逐步恢复 |
| 长稳运行 | 全场景混合负载 24 小时 | 1000 连接 + 低强度调用 | 无内存泄漏（RSS 漂移小于 10%）、无 goroutine 泄漏 |

### 6.3 基线采集方法

- 预发环境双实例拓扑（与生产同构），压测前记录冷基线（空闲 CPU/内存/连接数）。
- 指标经 Prometheus + Grafana 采集：连接数、goroutine 数、Valkey 命中率、PG 慢查询、P95/P99 直方图；埋点事件必须含 trace_id 与 tenant_id（NFR-006）。
- 每档压测重复 3 次取中位数，报告附原始数据与资源水位曲线。
- 容量结论方法：从 1000 台结果线性外推 1 万台需求，输出扩容建议；外推不达标即触发数据面扩容与设备会话模型优化（doc/05 第 8 节风险对策）。

### 6.4 通过标准

全部目标指标达标、24 小时长稳无泄漏、限流场景 429 生效、1000 台容量验证通过，压测报告归档后性能门禁通过。

## 9. 缺陷管理

### 9.1 缺陷分级

| 级别 | 定义 | 示例（对应本计划） |
|------|------|-------------------|
| P0 阻断 | 核心链路不可用或安全边界可绕过，且无规避方案 | 高危指令绕过 HITL 执行；跨租户调用成功；回调无签名可放行 |
| P1 严重 | 核心功能错误或有规避方案的安全缺陷 | 跨节点审批无法唤醒；审计记录缺失；凭证吊销不生效 |
| P2 一般 | 非核心功能错误、性能不达标、边界异常处理缺陷 | 单条异常消息处理错误；界面显示错误 |
| P3 轻微 | 不影响使用的体验问题 | 文案笔误、提示不友好 |
| P4 建议 | 优化建议 | 性能优化点、可观测性增强 |

### 9.2 处理 SLA 与流程

| 级别 | 修复时限 | 复核时限 | 说明 |
|------|---------|---------|------|
| P0 | 24 小时内出修复版本 | 修复当日复核 | 修复后跑该缺陷关联用例 + 对应模块冒烟集 |
| P1 | 3 个工作日内 | 2 个工作日内 | 回归范围含同模块全部 P0/P1 用例 |
| P2 | 当迭代内修复或明确延期 | 迭代末 | 延期需质量评审会批准 |
| P3/P4 | 排期处理 | 不阻断 | 累计至迭代末统一评估 |

- 缺陷报告模板：环境信息（Compose 拓扑、服务版本）、最小复现步骤、期望与实际行为、关联用例 ID、日志与 trace_id。不能稳定复现的缺陷视为未修复。
- 缺陷评审：每迭代末由测试、开发、产品三方评审未关闭缺陷，输出缺陷趋势与归因（模块、阶段、注入原因）。
- 上线阻断标准：P0/P1 未清零；SEC-01 至 SEC-14 任一验证未通过；网关契约测试任一失败（GW-001 至 GW-010、XL-001 至 XL-005）；性能门禁未达标；E2E 必跑集任一条失败，五项任一成立即阻断上线。
