- 升级前备份：Compose `adc_backup` 卷内 `/backup/m8/pre-v2.1.dump`。
- 完整性：已生成 SHA-256 文件并通过 `pg_restore -l` 格式检查。
- 迁移账本：目标版本 6，版本 1-6 连续。
- 目标版本来源：`ce/migrations/*.up.sql` 的最新文件 `0006_developer_applications.up.sql`，smoke 校验 `MIN(version)=1` 且 `COUNT(*)=MAX(version)=目标版本=6`，不再仅检查版本大于 0。
- 回滚策略：切回升级前不可变应用镜像，不执行 down migration，不删除 PostgreSQL 或 Valkey 命名卷。
- 数据恢复：仅在应用回滚无法读取向前 schema 或数据损坏时使用备份恢复。

## 五、残余风险与线下条件

以下事项不以本地模拟结论替代，正式 `v0.3.0` tag 前必须单独决策或验收：

1. 使用真实客户 IdP 验证私有 CA、JWKS 轮换、NTP 偏差、MFA claim 和身份预映射。
2. 在 amd64 与 arm64 原生 Linux 主机验证镜像安装、升级和回滚；QEMU 构建不替代原生运行。
3. 在断网独立 VM 验证离线包安装、迁移、升级和回滚闭包。
4. 完成 OIDC、白标、预算等能力的 CE/EE 商业装配边界评审；仓库许可证战略本阶段未改变。
5. Python A2A 任务持久化与多副本一致性已在 V2.2 M9 完成；本报告保留该项作为 M8 验收时点的历史残余记录，当前状态以 `design/85-V2.2-M9验收报告.md` 为准。
6. 正式等保测评、真实工业设备和厂商 SDK 联调仍为线下工作。
7. 历史 `auth_source='OIDC'` 用户仅在 metadata 同时含非空 `oidc_issuer` 与 `oidc_subject` 且组合唯一时自动回填。`adc_oidc_identity_quarantine` 中 `MISSING_ISSUER`、`MISSING_SUBJECT` 或 `DUPLICATE_IDENTITY` 记录必须由管理员依据原 IdP 台账人工确认并写入 `adc_oidc_identities`；迁移不会猜测 issuer，隔离用户在映射完成前无法通过 OIDC 登录。
8. 本轮仅将 `Dockerfile.pyagent` 的 uv 镜像固定为已知版本 `0.8.13`；其余 Dockerfile 与 Compose 基础镜像尚未固定 digest，须在正式生产发布前完成 digest 锁定与定期更新机制。本报告不将该项记为已完成。

## 六、验收结论

V2.1 M8 的本地工程目标已完成：未验签 OIDC 路径已被安全实现替代，既有数据卷可自动迁移，开发者应用凭证形成最小闭环，中英与发布门禁可重复执行，Compose 已重新构建发布并通过扩展 smoke。

本报告建议用户对 M8 本地工程交付执行验收。用户验收前不创建正式 `v0.3.0` tag，不归档 OpenSpec 变更。
