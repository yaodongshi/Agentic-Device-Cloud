## 0. 结论摘要（结论先行）

1. **总体结构**：V1.0 按"控制面/数据面轻拆分"（ADR-01 方案 B）划分为 **10 个模块**：控制面 2 个（Admin API、控制台前端），数据面 4 个（Device Connector、Agent API、Approval Service、审计服务），Agent 面 1 个（M9 Python Agent 面），网关层 1 个（M10 统一 API 网关），旁路 1 个（LLM 网关），边缘 1 个（边缘 SDK）。技术栈按方案 A 双语言布局（ADR-19/20，design/70）：控制面/数据面/网关为 Go，Agent 面为 Python（FastAPI/uvicorn，ce/py-agent）；全部业务模块共享同一 monorepo 代码库（ADR-12），按进程装配区分运行形态。
2. **依赖铁律**：依赖方向单向、禁止成环——控制台前端与全部外部客户端只依赖 M10 统一 API 网关（前端无感原则，见 2.5）；网关只转发不持业务状态；控制面与数据面互不直接调用，共享数据一律经 PostgreSQL 收敛；数据面内部唯一跨模块调用链是 Agent API 到 Approval Service（工单创建）；业务模块对消息层一律经"消息抽象接口"访问，不感知 Valkey 具体实现。
3. **三条 V1.0 过渡设计**（阶段 2 之前不得提前引入）：消息层用 Valkey Pub/Sub/List 过渡（NATS JetStream 阶段 2，ADR-02）；风险判定用 DB risk_level 过渡（OPA 阶段 2，ADR-07）；设备接入仅 B 类 Legacy Bridge（A 类原生 MCP 设备 V1.5、A2A 委派 V1.5 起由 M9 承载，ADR-15/20）。三者均以 seam 接口预留演进位。
4. **安全底线**：SEC-01~14 全部修复作为 V1.0 硬性验收项纳入本设计（审批回调验签、Agent API Key 租户绑定、设备 HMAC nonce 防重放、全链路 TLS、工单 PG 主存、限流、审计落库、路由续期），任何一条未过验收 V1.0 不得发布。
5. **开源边界**：V1.0 主交付 ce/（LGPL-3）；core-sdk/（Apache-2.0）只承载 wire 协议与 B 类 SDK（协议类型 Go/Python 双语言，契约由 OpenAPI/JSON Schema 驱动，ADR-20）；ee/（源码可见商业许可）经 seam 接口装配（ADR-14），V1.0 冻结首批 5 个 seam 接口并语义化版本管理。
6. **前端无感原则**：前端契约唯一来源为 M10 网关对外 OpenAPI；后端语言（Go/Python）、路由、服务拆分变更一律在网关内部消化，不触达前端（见 2.5）。

## 1. 引言

### 1.1 目的

本文档定义 ADC V1.0 MVP 的概要设计：模块划分与职责边界、模块间依赖方向、关键数据流、跨模块接口契约方向、技术决策在 V1.0 的落地边界、错误与降级策略、安全设计概要、部署形态。本文档是 design/31~33 详细设计（LLD）与 design/60 部署方案的上级约束文件，也是 openspec 变更中任何涉及模块边界改动的对照基准。

### 1.2 范围

**设计范围（V1.0 MVP）**：

- 控制面：租户管理、设备台账（B 类登记/吊销/启用）、Agent API Key 管理、工具风险等级配置、审批流配置、审计查询、基础用量统计（只打点不结算）。
- 数据面：B 类设备经 Legacy Bridge（WSS + HMAC+nonce + tools/list + tools/call）接入；Agent 工具聚合与调用路由；单级 HITL 审批（工单 PG 主存）；异步审计落库；Valkey 承载路由索引、跨节点路由、审批唤醒、审计缓冲。
- 网关层：M10 统一 API 网关（Go），前端唯一入口，按路径前缀路由、统一 TLS 终结、会话校验透传、限流、契约校验；前端只配置一个网关地址，后端语言/路由变更对前端无感（前端无感原则，见 2.5）。
- Agent 面（V1.0 最小集）：M9 Python Agent 面（Python 3.14 + FastAPI/uvicorn）交付评测工具链与开发脚本（ce/py-agent，uv 治理）；LLM 网关编排、Agent 编排、A2A Agent Card 等完整能力自 V1.5 起（FR-012/022/024，ADR-20）。
- 横切：全栈 i18n 中英就绪（后端消息 i18n、前端文案键化、审批卡片双语）；结构化日志与基础 Prometheus 指标。
- 部署：Docker 多架构镜像 + Compose 单机起步，可拆分运行（ADR-09）。
- 安全：SEC-01~14 修复全部纳入（详见第 6 章）。

**不在范围（明确排除）**：

| 项 | 归属版本/阶段 | 依据 |
|---|---|---|
| A 类原生 MCP 设备接入（OAuth 2.1 鉴权绑定、平台作 MCP Client） | V1.5（阶段 2） | ADR-15、doc/07 |
| A2A 网关与内部多 Agent 编排 | V1.5 起由 M9 Python Agent 面承载（A2A Agent Card、Agent 编排，FR-022/024）；V2.0 按 ADR-16/17 深化 | ADR-16/17、ADR-20 |
| NATS JetStream 消息层 | V1.5（阶段 2） | ADR-02 |
| OPA 策略引擎 | V1.5（阶段 2），V1.0 用 DB risk_level 过渡 | ADR-07 |
| 多级审批、多租户 RBAC/SSO、计量计费结算、多区域 cell、集群 HA、等保模块 | ee/ 商业化版本 | ADR-11、doc/04 |
| C 类哑设备直连 | 永久排除，经边缘盒子聚合为 B 类接入 | doc/07 2.1 |
| 边缘断网自动重放（只做本地队列缓存，不自动执行） | V1.5+ | doc/05 阶段 4 回退策略 |

### 1.3 术语

| 术语 | 定义 |
|---|---|
| A 类设备 | 固件内嵌 MCP Server 运行时的原生 MCP 设备（V1.5 接入） |
| B 类设备 | 跑边缘 SDK、经 Legacy Bridge（WSS 反向隧道）桥接的设备，V1.0 唯一接入路径 |
| C 类设备 | 仅现场总线（Modbus/CAN/EtherCAT）的遗留哑设备，平台不直接支持 |
| Legacy Bridge | 原 PoC WSS 反向隧道保留路径，用于 B 类设备桥接（ADR-15 降级定位） |
| HITL | Human-in-the-Loop，高危工具调用的人工审批熔断机制 |
| seam 接口 | ce/ 与 ee/ 之间的装配接口（接口 + 运行期插件注册，ADR-14），是公开契约 |
| 消息抽象接口 | 业务模块访问消息层的统一接口（发布/订阅/请求应答），V1.0 实现为 Valkey 适配器，阶段 2 换 JetStream 适配器 |
| 路由索引 | Valkey 中"设备 -> 所在 Connector 节点"的映射（带 TTL 与续期） |
| fail-safe | 审批超时默认拒绝，宁可阻断不静默放行 |
| 统一 API 网关（M10） | 前端唯一入口的 Go 网关服务：统一 TLS 终结、会话校验透传、限流、契约校验与按路径前缀路由（/v1/*→Go 服务、/v2/agents/*→Python Agent 面）；后端语言/路由变更对前端无感 |
| Python Agent 面（M9） | Python 3.14 + FastAPI/uvicorn 实现的 Agent 面：LLM 网关编排、Agent 编排、A2A Agent Card、评测工具链；V1.0 最小集交付评测工具链与开发脚本，V1.5 起完整承载 FR-012/022/024 |
| 前端无感原则 | 前端契约唯一来源为 M10 网关对外 OpenAPI；后端语言/路由/服务拆分变更不触达前端，仅网关内部路由表与契约演进 |
| 评测工具链 | M9 V1.0 最小集交付物：工具调用与 Prompt 评测脚本、基线数据与开发脚本（ce/py-agent 内独立工具） |

底座依赖（V1.0）：PostgreSQL 16+（状态与审计主存）、Valkey 8+（ADR-13，路由/唤醒/缓冲/限流计数）。OPA 与 NATS JetStream 为阶段 2 组件，V1.0 不部署但以接口预留。

依赖规则（评审与合入门禁，违反即拒绝合并）：

1. **单向依赖、禁止成环**：上图箭头方向即允许的调用方向；任何反向调用（如数据面调用 Admin API、业务服务回调用网关）视为架构违规。
2. **外部客户端只依赖 M10 网关**：前端/Agent 客户端/外部编排 Agent 是唯一需要感知网关地址的角色（前端无感原则，见 2.5）；禁止前端直连任何业务服务或直连 PG；网关只做路由/透传/校验，不持业务状态、不读写 PG/Valkey，业务鉴权决策一律下放服务。
3. **控制面与数据面互不直接调用**：台账、凭证、风险等级等共享数据一律经 PostgreSQL 收敛，读取方直接读库或缓存，不跨面调用接口；这是故障域隔离的基础。
4. **业务模块只依赖消息抽象接口**：禁止直接使用 Valkey 客户端命令书写业务逻辑（M3/M4/M5/M9 内部经接口适配），保证阶段 2 JetStream 替换不改业务代码。
5. **LLM 网关旁路不拦截主链路**：V1.0 任何设备调用链不经过 M7；M7 故障不影响数据面。
6. **M2 是 M1 的唯一 Web 消费者**；审计查询只经 M6 查询接口或 M1 转查询接口，禁止前端直连 PG。
7. **M9 与数据面进程边界隔离**：不共享内存状态，交互仅经内网服务间 HTTP 与消息抽象接口（MessageBus，ADR-02）；对外一律经 M10 网关。

### 2.5 前端无感原则

1. **前端契约唯一来源**：M10 网关对外暴露的合并 OpenAPI 契约（由各服务契约经网关汇聚、语义化版本管理）是前端唯一契约来源；前端只配置一个网关地址，不配置任何业务服务地址。
2. **后端变更不触达前端**：后端语言（Go/Python）实现替换、服务拆分合并、内部路由调整，一律在网关路由表与契约层消化；前端依赖的路径前缀（/v1/admin/*、/v1/agent/*、/v1/devices/tunnel、/v1/hitl/*、/v2/agents/*）与响应语义保持稳定，前端零改动。
3. **契约演进纪律**：网关契约校验保证请求/响应符合 schema（CONTRACT_INVALID，见 5.1）；契约变更走 design/33 评审与语义化版本管理——新增字段默认可选、禁止破坏性删除；前端按契约版本升级而非随后端部署节奏。
4. **新增后端服务** = 网关新增路径前缀路由 + 契约合并，经 openspec 变更评审后即可发布，前端无感知。

### 2.6 三仓与目录结构

- **ce/**（LGPL-3，V1.0 主交付）：原有 Go 模块（cmd/、internal/、migrations/，M1/M3/M4/M5/M6/M10）保持；**新增 `ce/py-agent/` 目录承载 M9 Python Agent 面**——Python 3.14 + FastAPI/uvicorn，包名 adc-agent；依赖治理采用 uv：`pyproject.toml` 声明依赖 + `uv.lock` 锁定（`uv sync --frozen`），CI 与离线交付使用 wheelhouse（uv cache + `--offline`）固化依赖；与 Go 模块同仓并行演进，CI 独立构建验证互不污染。
- **core-sdk/**（Apache-2.0）：wire 协议与 B 类 SDK；**协议类型双语言（Go 与 Python 各一份实现）**，契约由 OpenAPI/JSON Schema 驱动生成，Go/Python 双语言实现必须同源契约、CI 校验一致性（ADR-20）；Python 协议实现供 M9 评测工具链与 V1.5+ Linux 盒子级 Python SDK 复用。
- **ee/**（源码可见商业许可）：经 seam 接口装配（ADR-14），不含 py-agent 商业面演进（如需独立商业化，另行 openspec 变更）。

### 3.0 HLD 与 LLD 的边界说明

**HLD（本文件）管**：模块边界、职责、对外接口清单（路径与语义方向，不含字段级定义）、依赖方向、状态归属、并发一致性策略、seam 扩展点、运行形态。**LLD 管**：包结构与文件划分、数据表 DDL、接口字段级契约、算法与状态机实现细节、单元测试矩阵。LLD 不得反向改动 HLD 的模块边界与依赖方向；若 LLD 设计中发现边界问题，必须先提 openspec 变更修订本文件。

| design/60 | 全部 | Compose 编排、多架构构建、私有化离线交付、监控告警部署（M7/M9/M10 部署细节归此；M9 完整 Agent 面部署自 V1.5 起） |

### 3.1 M1 Admin API [EE]

- **职责**：控制面唯一后端入口。租户 CRUD；设备台账管理（B 类设备登记/启用/吊销/凭证轮转，device_class 字段预留 A 类）；Agent API Key 签发/吊销（哈希存储）；工具风险等级配置（写 adc_device_tools.risk_level，默认等级 2 先审后用）；审批流配置（审批人列表/超时时长/通知渠道/语言偏好）；审计查询（转 M6 查询接口）；用量打点查询（只读）。
- **对外接口摘要**：

| 接口 | 方法 | 说明 |
|---|---|---|
| /api/v1/tenants、/api/v1/tenants/{id} | GET/POST/PUT/DELETE | 租户管理 |
| /api/v1/devices、/api/v1/devices/{id}/revoke | GET/POST/PUT/DELETE | 设备台账与吊销 |
| /api/v1/agents、/api/v1/agents/{id}/keys | GET/POST/DELETE | Agent 与 API Key 管理 |
| /api/v1/tools/{device_id}/{tool_name}/risk | PUT | 风险等级权威覆盖 |
| /api/v1/hitl-policies | GET/PUT | 审批流配置 |
| /api/v1/audit/logs | GET | 审计查询（委托 M6） |
| /api/v1/metrics/usage | GET | 用量打点查询 |

- **内部组件**：HTTP 服务层、管理员认证中间件（V1.0：HTTPS + 用户名口令 + 会话，SSO/OIDC 为 EE 演进项）、RBAC 校验器（租户内角色）、资源处理器、审计事件发布器、i18n 消息包（go-i18n）。
- **状态与并发模型**：无进程内业务状态，全部状态以 PG 为唯一主存；凭证签发/吊销走事务与唯一约束；轮转采用"新旧双槽并行 24 小时"策略（doc/07 2.3 延伸至 B 类）。
- **扩展点（ee/ seam）**：M1 自身即 EE 模块，不对外暴露 seam；其依赖的 ce/ 能力（审计查询、凭证校验）经 M6 查询接口与 PG 访问，不侵入 ce/ 构建。
- **运行形态**：拆分形态为独立进程（容器），端口 8081，仅内网暴露（经 M10 网关 /v1/admin/* 路由，M2 不直连）；单机形态与数据面同机部署但保持独立进程（Compose 单机仍分容器），目标形态可随 ee/ 交付包与 M2 静态资源打包为一个控制面进程。

### 3.2 M2 控制台前端 [EE]

- **职责**：租户/设备/Agent/风险等级/审批流/审计/用量等管理页面；审批记录浏览；操作审计留痕展示；全站中英双语切换。
- **对外接口摘要**：无对外服务接口；唯一依赖经 M10 网关暴露的 REST API（/v1/admin/* 前缀，前端无感原则）；资源包（i18n key-value JSON）随版本发布。
- **内部组件**：Vue 3 + TypeScript + Vite + Element Plus；Pinia 状态管理；路由守卫（登录态与角色权限）；API client 层（统一错误码与 i18n 文案映射，仅配置网关地址）；vue-i18n 资源包。
- **状态与并发模型**：仅客户端会话状态（登录态、当前租户上下文、语言偏好）；所有服务端状态经 M1 读写；语言优先级：用户偏好 → 浏览器 Accept-Language → 平台默认 zh-CN。
- **扩展点（ee/ seam）**：EE 内部采用页面/菜单注册表，供后续等保、计量等 EE 特性扩展；不得引入对 ce/ 的任何编译期依赖。
- **运行形态**：拆分形态为 nginx 托管的静态资源容器（与反向代理合并为 edge 服务）；单机形态为同一静态资源容器，仅后端地址配置不同。

### 3.3 M3 Device Connector [CE]

- **职责**：B 类设备唯一接入点。WSS 隧道接入（TLS 终结、Origin 白名单、子协议版本校验，SEC-04/05）；设备认证（HMAC 挑战：DB 加载凭证、nonce+timestamp 时间窗校验、nonce 缓存防重放、吊销列表，SEC-03）；会话管理（会话表、心跳、重连踢旧、断连清理，SEC-14/15/17）；工具目录同步（tools/list 拉取、list_changed 增量刷新、risk_level 权威值回写台账）；路由索引维护（Valkey TTL 续期）；工具调用下发（本节点直连快速路径 + 跨节点经消息抽象接口转发）；路由归属声明（"会话归属以本地为准，Valkey 只作索引"）。
- **对外接口摘要**：

| 接口 | 方法 | 说明 |
|---|---|---|
| /v1/devices/tunnel | WSS | 设备隧道接入（TLS，认证后建立会话） |
| （内部）设备凭证读取 | - | 直读 PG 凭证表（缓存 + 吊销缓存，不调 M1） |
| （内部）路由索引与跨节点通道 | - | 经消息抽象接口（Valkey 适配器） |
| /healthz、/metrics | GET | 健康检查与指标（Prometheus） |

- **内部组件**：WSS 接入点（TLS + Origin 白名单 + 全量超时配置，SEC-19）；认证器（HMAC 挑战、nonce 缓存、凭证缓存）；会话管理器（进程内会话表 + 心跳定时器 + 断连回调）；工具目录同步器（缓存 + 台账异步写）；路由索引器（Valkey TTL 90s/续期 30s）；本地执行器（15s 超时，长任务模型 V1.5 按 ADR-10 演进）；跨节点转发器（消息抽象接口，超时与错误映射）。
- **状态与并发模型**：进程内会话表为唯一会话归属权威，Valkey 索引为可重建的派生数据（GAP-11 双源漂移治理）；会话操作加锁，断连回调校验会话指针防误删新会话（SEC-15）；nonce 缓存带 TTL；工具目录缓存以 list_changed 事件失效。
- **扩展点（ee/ seam）**：
  - **消息抽象接口**（V1.0 冻结）：publish/subscribe/request 三原语，Valkey 适配器实现；阶段 2 JetStream 适配器同接口替换（ADR-02 预留）。
  - **设备接入分支预留**（V1.5）：注册治理接口接受 device_class 参数，'A' 分支走 MCP Client + OAuth 2.1（doc/07 2.2），V1.0 只实现 'B' 分支；数据模型字段（mcp_endpoint/auth_endpoint/public_key_fp/binding_status）在 V1.0 建表时一并落地（doc/07 2.5）。
  - **长任务执行 seam**（V1.5）：本地执行器预留任务 ID 返回路径，阶段 2 接 ADR-10 异步模型。
- **运行形态**：拆分形态为独立进程（端口 8443），可水平扩展（设备经负载均衡分配到不同 Connector，跨节点调用走消息层）；单机形态与其他数据面模块装配于同一 adc-server 进程。

### 3.4 M4 Agent API [CE]

- **职责**：Agent 统一入口。API Key 认证与租户强绑定（租户上下文只取自凭证，绝不信任请求头，SEC-02）；工具聚合视图（跨节点聚合、租户隔离、i18n 按 Agent 语言下发工具描述）；tools/call 结构化路由（device_id 独立字段，禁止 "__" 分隔，SEC-24）；风险判定（RiskPolicy 接口，V1.0 实现读 DB risk_level 缓存，SEC-09）；HITL 拦截编排（高危时创建工单并返回 202 挂起）；同步调用超时（15s，SEC-16 长任务 V1.5 演进）；三维度限流（SEC-12）；审计事件发布（SEC-07）；V1.5 起作为 M9 Agent 编排的设备工具执行上游（内网服务间调用）。
- **对外接口摘要**：

| 接口 | 方法 | 说明 |
|---|---|---|
| /v1/agent/mcp/tools | POST | 工具聚合列表（认证后按租户裁剪） |
| /v1/agent/mcp/tools/call | POST | 工具调用（结构化 device_id + tool_name + arguments） |
| （内部）工单创建 | - | 调用 M5（进程内或服务间，见运行形态） |
| （内部）路由请求 | - | 经消息抽象接口 |
| /healthz、/metrics | GET | 健康检查与指标 |

- **内部组件**：认证中间件（API Key 哈希比对 + 租户绑定 + 凭证吊销缓存）；限流器（token bucket：每租户/每 Agent/每设备三维度）；工具聚合器（租户级缓存，list_changed 失效）；风险策略接口实现（DBRiskPolicy）；调用编排器（免审直路由 / 审批挂起 / 超时与错误映射）；审计发布器。
- **状态与并发模型**：无会话态（可水平扩展）；工具聚合缓存与 risk_level 缓存为只读派生数据，失效以事件驱动；挂起调用等待表持有请求上下文，由 M5 唤醒事件驱动续跑；并发审批以 M5 侧 CAS 唯一生效（SEC-11）。
- **扩展点（ee/ seam）**：
  - **RiskPolicy 接口**（V1.0 冻结）：`Evaluate(ctx, tenant, device, tool, args) (level, hitlRequired, reason)`；V1.0 实现 DBRiskPolicy（读 risk_level，默认 2 先审后用），阶段 2 OPA 实现同接口替换（ADR-07 预留）。
  - **MeteringHook 接口**（EE 计量打点，V1.0 只打点不结算）。
  - **配额接口**（EE 扩展 Agent 调用配额）。
- **运行形态**：拆分形态为无状态独立进程（端口 8080），水平扩展；单机形态装配于 adc-server；与 M5 的工单创建调用在单机形态为进程内调用，拆分形态为服务间调用（协议一致，LLD 定细节）。

### 3.5 M5 Approval Service [CE 单级 + EE 多级]

- **职责**：HITL 工单全生命周期。工单创建（PG 主存，ADR-05/SEC-08）；审批通知推送（企微/钉钉卡片，i18n 双语模板，含签名回调 URL，SEC-13）；回调验签（HMAC 签名 + 时效 + 一次性消费）与 OAuth 审批人真实身份（SEC-01/21）；状态机原子更新（CAS/乐观锁 + 过期校验，SEC-11）；过期 fail-safe（默认拒绝，超时可配）；挂起调用唤醒（Valkey adc:hitl:* 统一订阅 + 本地路由，SEC-10 修复）；推送失败重试与降级（指数退避 + 告警，SEC-18）。
- **对外接口摘要**：

| 接口 | 方法 | 说明 |
|---|---|---|
| /v1/hitl/action | GET/POST | 审批回调（签名参数 + 一次性消费，经 M10 网关 /v1/hitl/* 对外） |
| （内部）CreateTicket | - | 供 M4 调用 |
| （内部）唤醒事件 | - | Valkey 通道（经消息抽象接口） |
| /healthz、/metrics | GET | 健康检查与指标 |

- **内部组件**：工单状态机（PENDING → APPROVED/REJECTED/EXPIRED，PG 行锁 + 唯一约束）；工单仓储（PG）；通知适配器（WeCom/DingTalk 接口 + 卡片模板 + i18n 资源包）；回调验证器（签名/时效/租户绑定）；唤醒广播器（本地等待表 + 通道订阅）；过期回收器（定时扫描置 EXPIRED）。
- **状态与并发模型**：工单状态以 PG 为唯一主存（不可抵赖），Valkey 仅唤醒广播与通知去重计数；进程内等待表（ticketID → 等待者）随重启重建（工单在 PG，重启后可查、等待方经超时或续查恢复）；并发审批唯一生效由 CAS 保证；过期校验 now < ExpireAt 为硬约束。
- **扩展点（ee/ seam）**：
  - **ApprovalChain 接口**（V1.0 冻结）：V1.0 单级实现；EE 多级审批同接口替换。
  - **Notifier 接口**：多渠道适配（V1.0 企微/钉钉；EE 短信/邮件）。
  - **A2A 映射预留**（V1.5 起，M9 承载）：工单状态命名与 doc/07 3.2 的 A2A TaskState 映射契约对齐（PENDING→input-required 等），V1.0 状态值即按该契约设计，避免 V1.5 迁移改状态语义。
- **运行形态**：拆分形态为独立进程（端口 8082，回调经 edge→M10 网关 /v1/hitl/* 对外）；V1.0 单实例写工单（CAS 依赖单写者语义简化），多实例仅分摊通知推送；单机形态装配于 adc-server。

### 3.6 M6 审计服务 [CE]

- **职责**：全平台审计留痕。接收各模块结构化审计事件（工具调用、审批决策、管理操作）；Valkey List 缓冲消费与批量落 PG 分区表（按月分区）；字段完整性与主体真实性校验（agent_id/approver 必须为真实主体，SEC-21）；查询接口（按租户/时间/主体/设备/工具过滤）；留存策略配置。
- **对外接口摘要**：

| 接口 | 方法 | 说明 |
|---|---|---|
| （内部）审计事件接收 | - | Valkey List RPUSH（业务模块经审计发布器） |
| /internal/audit/query | GET | 供 M1 委托查询（服务间调用） |
| /healthz、/metrics | GET | 健康检查与指标 |

- **内部组件**：缓冲消费者（BLPOP 批量拉取 + 消费位点记录）；批量写入器（事务批量 INSERT）；分区表管理器（自动建月分区）；查询服务（索引：tenant_id + created_at）；事件 schema 校验器。
- **状态与并发模型**：无业务状态；消费位点存 Valkey，重启续消费；写入幂等（事件 ID 唯一约束，重试不重复落库）；查询只读。
- **扩展点（ee/ seam）**：事件通道接口（V1.0 Valkey List 适配器 → 阶段 2 JetStream 适配器，ADR-06 终态）；查询权限策略（EE 控制台角色细粒度过滤）。
- **运行形态**：拆分形态为独立进程（端口 8083，仅内网）；单机形态装配于 adc-server。

### 3.7 M7 LLM 网关旁路 [CE 底座 + EE 计量]

- **职责**：V1.0 定位为旁路组件，不在任何设备调用主链路上。提供模型 API 统一代理（litellm，OpenAI 兼容协议）；Token 计量打点（写 PG 计量表，EE 查询）；Langfuse 调用链追踪（可选开启）；模型密钥集中注入（环境变量/KMS，SEC-13 精神）。
- **对外接口摘要**：

| 接口 | 方法 | 说明 |
|---|---|---|
| /v1/llm/* | POST | 模型代理（供租户侧 Agent 与后续内部 Agent 使用） |
| /healthz、/metrics | GET | 健康检查与指标 |

- **内部组件**：litellm 部署实例；计量采集器（token 计数 → PG 计量打点表）；追踪导出器（Langfuse，可选）；密钥注入层。
- **状态与并发模型**：无状态；计量打点异步批量写。
- **扩展点（ee/ seam）**：计量钩子（EE 结算用，V1.0 只打点）；V1.5 起 LLM 网关编排逻辑归 M9（Python Agent 面）消费本模块作为模型代理底座（FR-012）；V2.0 起嵌入 A2A 多 Agent 编排链路的模型调用上游。
- **运行形态**：独立容器（端口 4000），单机与拆分形态相同；V1.0 为可选部署组件，未部署时不影响任何主链路功能。

### 3.8 M8 边缘 SDK [SDK，core-sdk/]

- **职责**：B 类设备的平台侧契约实现。wire 协议 v1（tools/list、tools/call、心跳、list_changed，协议头含版本字段，GAP-06 协商预留）；WSS 客户端（TLS 强制、重连指数退避、Origin/子协议合规）；HMAC 挑战签名（shared secret + nonce + timestamp，双槽轮转支持，SEC-03）；工具注册 API（设备侧声明工具与风险建议值 annotations + x-adc 扩展，doc/07 2.4 双层模型）；断连本地队列缓存（只缓存不自动重放，V1.5 开放重放）。
- **对外接口摘要**：

| 接口 | 说明 |
|---|---|
| C API（V1.5 交付） | 工具注册、调用分发、连接生命周期回调 |
| Go 参考实现（V1.0 交付） | 与 C API 同语义，供早期设备厂商与测试工具使用 |
| Python SDK（V1.5+ 可选交付） | Linux 盒子级：官方 MCP Python SDK 封装（FastMCP，Streamable HTTP/stdio），复用 core-sdk Python 协议实现 |
| wire 协议 v1 文档 | core-sdk/ 内冻结（OpenAPI/JSON Schema 驱动，Go/Python 双语言实现，ADR-20），语义化版本管理 |

- **内部组件**：协议编解码器（JSON-RPC 2.0 + 版本字段）；认证签名器（HMAC-SHA256，双密钥槽）；连接状态机（离线 → 连接 → 认证 → 在线 → 离线，重连退避）；工具注册表（含 annotations/x-adc 元数据）；本地队列（持久化，FIFO，容量上限）。
- **状态与并发模型**：连接状态机单实例驱动；队列与注册表线程安全；凭证双槽并行 24 小时轮转窗口。
- **扩展点（ee/ seam）**：core-sdk/ 独立仓库独立许可（Apache-2.0，零 copyleft，ADR-12），不含任何 ce/ee 代码；协议类型双语言（Go/Python）实现同源于 OpenAPI/JSON Schema 契约（ADR-20）；A 类形态（V1.5）由 SDK 演进出设备侧 MCP Server 运行时，wire 协议 v1 保持向后兼容。
- **运行形态**：MCU 级静态链接进设备固件或边缘进程（C/Rust），不在云端部署；Linux 盒子级 Python SDK 运行于边缘盒子进程（V1.5+ 可选）；V1.0 交付 Go 参考实现 + mock 设备改造（凭证环境变量注入，SEC-25）。

### 3.9 M9 Python Agent 面 [CE，ce/py-agent]

- **职责**：平台 Agent 面。**V1.0 最小集**：评测工具链（工具调用与 Prompt 评测脚本、基线数据）与开发脚本，支撑 Agent 面工程质量与后续演进；**V1.5 起完整承载**：LLM 网关编排（FR-012，多供应商路由/计量/故障转移编排，模型代理底座复用 M7 litellm）、Agent 编排（FR-024，Planner/设备选择/执行/HITL 四 Agent 流水线）、A2A Agent Card 发布与外部委派接收（FR-022）。
- **技术选型**：Python 3.14 + FastAPI + uvicorn；Agent 生态采用官方 MCP Python SDK 与 A2A SDK（design/70 评估：Agent 面生态 Python 显著优于 Go）；依赖经 uv 治理（pyproject.toml + uv.lock，离线 wheelhouse）。
- **对外接口摘要**：

| 接口 | 方法 | 说明 |
|---|---|---|
| /v2/agents/* | 按功能定 | Agent Card 获取/委派接收/任务状态查询（V1.5 起；经 M10 网关路由，不直接暴露公网） |
| /v2/agents/eval/* | POST | 评测工具链服务化入口（V1.0 起，开发/CI 环境使用） |
| /healthz、/metrics | GET | 健康检查与指标 |

- **内部组件**（V1.0 最小集）：评测运行器（工具调用评测、Prompt 评测、基线比对）、开发脚本工具集、OpenAPI 契约生成器（复用 core-sdk 双语言契约）。
- **状态与并发模型**：V1.0 最小集无生产状态（评测数据落本地/CI 产物）；V1.5 起任务状态与 A2A TaskState 对齐（doc/07 3.2），落 PG 与消息层，进程内不持有权威状态；与数据面进程边界隔离，不共享内存。
- **扩展点（ee/ seam）**：V1.5 完整面引入前须经 openspec 变更评审；多租户多 Agent 治理、编排策略中心等 EE 能力经 seam 接口装配（FR-022/024 开源边界，doc/03）。
- **运行形态**：V1.0 最小集为开发期工具（CI/本地运行），不进入生产 Compose；V1.5 起独立容器（仅内网，前端经 M10 网关 /v2/agents/* 访问）。

### 3.10 M10 统一 API 网关 [CE]

- **职责**：前端唯一入口（Go 实现）。按路径前缀路由：/v1/admin/*→M1、/v1/agent/*→M4、/v1/devices/tunnel→M3（WSS）、/v1/hitl/*→M5、/v2/agents/*→M9；统一 TLS 终结；会话校验透传（校验签名与有效期，不解析业务语义——租户上下文仍由业务服务从凭证解析，SEC-02 精神）；接入层限流（业务三维度限流仍在 M4 执行，SEC-12）；契约校验（请求/响应按网关合并 OpenAPI 校验，NFR-004 精神）；traceId 注入贯穿。前端无感原则（2.5）的落点。
- **对外接口摘要**：

| 接口 | 方法 | 说明 |
|---|---|---|
| 全部客户端入口 | 按路由前缀 | 前端/Agent 客户端唯一可达地址（经 edge nginx 暴露 443） |
| /healthz、/metrics | GET | 健康检查与指标（含路由表配置版本） |

- **内部组件**：路由表（配置驱动，语义化版本，变更走 design/33 评审）；TLS 终结器（证书注入与轮转随 design/60）；会话校验中间件（共享密钥签名验证，透传上下文头）；接入层限流器；契约校验器（OpenAPI 3 schema 校验）；请求日志与 traceId 注入。
- **状态与并发模型**：无业务状态，可水平扩展；不读写 PG/Valkey（故障域隔离，网关故障不影响业务服务既有会话）；多副本场景下会话校验为无状态签名验证，无会话复制。
- **扩展点（ee/ seam）**：新增后端服务=新增路径前缀路由 + 契约合并（前端无感）；EE 场景可叠加租户级接入策略（防 DDoS、专属域名），经 seam 接口扩展。
- **运行形态**：拆分形态独立进程；单机形态同样为独立进程（Compose 容器，与 adc-server 分离，保证入口单一与故障隔离）；对外仅经 edge nginx（80/443）暴露。

## 4. 关键技术决策摘要（V1.0 生效的 ADR）

下表仅列 V1.0 范围内生效或影响 V1.0 设计的决策，完整决策背景见 doc/05 第 5 章；与 doc/05 冲突时以 doc/05 为准并在 openspec 变更中修正。**ADR-19/20 为本文件新增决策（方案 A 双语言基线，决策记录见 design/70），doc/05 尚未收录，待后续 openspec 变更同步。**

| ADR | 选择 | 理由（摘要） | V1.0 落地边界 |
|---|---|---|---|
| ADR-01 服务拆分形态 | B：控制面/数据面轻拆分 | 单进程无法为控制面单独设防与扩缩容；全面微服务对当前团队过重 | 共用 ce/ 代码库，独立进程装配；M1/M2 控制面进程与 M3/M4/M5/M6 数据面进程分离；单机一体二进制（adc-server）兜底私有化极简交付 |
| ADR-02 跨节点消息通道 | C：NATS JetStream（终态） | Pub/Sub 无持久无重试会静默丢消息（SEC-10/14 根因） | **V1.0 不启用**；业务模块经消息抽象接口访问，V1.0 实现 Valkey 适配器（修复 SEC-10/14 于 Valkey 之上）；JetStream 适配器阶段 2 替换，业务代码零改动 |
| ADR-04 设备凭证方案 | B：HMAC + nonce + timestamp（先行），mTLS 为终态 | 立即消除重放，改动小；嵌入式证书成本高 | V1.0 全量落地于 B 类 Legacy Bridge：凭证 DB 加载、时间窗校验、nonce 缓存防重放、双槽轮转与吊销；mTLS 与 A 类设备一并归 V1.5 |

## 5. 错误处理与降级设计

### 5.1 错误码分层

三层体系，自下而上：**HTTP 状态码**（标准语义，网关与客户端通用）→ **业务错误码**（稳定英文 ID，契约，禁止以文案判分支）→ **i18n 文案**（资源包映射，可演进）。响应统一携带 traceId 便于链路检索。

| 业务错误码 | HTTP | 含义与处置 |
|---|---|---|
| AUTH_INVALID_TOKEN / AUTH_EXPIRED | 401 | 凭证无效/过期，客户端刷新或重新认证 |
| TENANT_FORBIDDEN | 403 | 租户绑定不符（SEC-02），拒绝且告警 |
| RATE_LIMITED | 429 | 触发限流（SEC-12），携带 Retry-After |
| TOOL_NOT_FOUND / DEVICE_NOT_FOUND | 404 | 工具/设备不存在或已吊销 |
| RISK_BLOCKED | 403 | 风险判定阻断（策略禁止或参数越界） |
| HITL_PENDING | 202 | 已创建审批工单，携带 ticket_id 与回调指引 |
| HITL_REJECTED / HITL_EXPIRED | 403 / 409 | 审批拒绝 / 过期 fail-safe（默认拒绝语义） |
| DEVICE_OFFLINE | 503 | 路由索引缺失或会话已断，客户端重试或换设备 |
| EXEC_TIMEOUT | 504 | 设备执行超时（V1.0 同步 15s 上限；长任务 V1.5 转异步） |
| CONTRACT_INVALID | 422 | 网关契约校验失败（请求/响应不符合网关 OpenAPI schema），客户端按契约修正 |
| INTERNAL / DEGRADED | 500 / 503 | 内部错误 / 依赖降级中 |

设备面错误经 M3 映射为 JSON-RPC Error（协议层），Agent 面错误经 M4 映射为 HTTP 语义，两端共用同一业务错误码 ID。

### 5.2 限流降级

- 三维度 token bucket（每租户/每 Agent/每设备独立桶，SEC-12）：Agent 调用限流（默认每 Agent 每秒 10 次，假设值，经 Admin API 可调）、设备连接数上限、审批卡片推送频控。
- 过载保护顺序：优先保设备下发链路（M4 限流先于 M3 会话）；限流触发返回 429 + RATE_LIMITED + Retry-After，不静默丢弃。
- 单机形态下限流计数存 Valkey（进程内计数为优化层），保证多进程装配语义一致。

### 5.3 设备离线处理

- 离线判定以"连接存续"为准（心跳随连接，30s 心跳 / 90s 索引 TTL / 每 30s 续期，SEC-14），Valkey 索引为派生数据可重建。
- 调用时路由 miss 返回 DEVICE_OFFLINE；V1.0 不缓存离线指令（Agent 侧自行重试策略）；审批挂起期间设备离线：工单保持 PENDING 不自动取消，设备上线后由 Agent 重试或审批人撤销。
- 断连主动清理索引并通知聚合缓存失效；重连踢旧会话（会话指针校验，SEC-15）。

### 5.4 审批超时

- 默认 fail-safe：超时即终态 EXPIRED（语义等同拒绝），宁可阻断不静默放行；超时时长经 M1 审批流配置（默认 5 分钟，沿用 PoC 值，假设值）。
- 过期校验为硬约束（now < ExpireAt，SEC-11）：过期工单回调一律拒绝并返回 HITL_EXPIRED。
- 通知降级链：企微推送 → 失败重试（指数退避）→ 钉钉备用 → 告警（SEC-18）；全部失败按超时 fail-safe 兜底并产生告警，不留静默失败路径。

### 5.5 依赖故障降级路径

| 故障 | 影响面 | V1.0 降级行为 |
|---|---|---|
| PostgreSQL 不可用 | 全平台 | 控制面转只读错误；数据面关键路径按缓存兜底（凭证缓存/工具缓存限时有效），无法兜底即快速失败返回 DEGRADED；工单创建失败时高危调用一律阻断（不绕审） |
| Valkey 不可用 | 跨节点路由/唤醒/限流计数 | 本节点直连快速路径不受影响（设备下发可用）；跨节点路由返回 DEGRADED；审批唤醒退化为超时兜底（fail-safe 仍成立）；限流退化为进程内保守计数（从严） |
| 企微/钉钉渠道不可用 | 审批通知 | 重试 + 备用渠道 + 告警（5.4 降级链），审批语义不变 |
| LLM 网关不可用 | 无主链路影响 | 旁路定位保证零影响；租户侧 Agent 收到 503 提示 |
| M10 网关不可用 | 前端全部入口 | 无状态多副本 + edge nginx 上游健康检查摘除故障实例（拆分形态）；V1.0 单机形态明确快速失败（503，不静默），恢复依赖容器重启策略；网关不持业务状态，恢复后不产生数据不一致 |
| 单机部署整机故障 | 全部 | 无冗余（ADR-09 单机形态定位）；恢复依赖 Docker 重启策略 + PG/Valkey 持久卷；99.9% SLA 目标属拆分部署 + V1.5 集群形态范畴 |

六条边界全部设防（对照 doc/05 2.1 五条 + 新增管理面），V1.0 验收标准为 doc/05 阻断级与严重级清零。补充边界 0：外部客户端（前端/Agent）→ M10 网关——统一 TLS 终结、会话校验透传、接入层限流、契约校验；网关不解析业务语义，租户上下文仍由业务服务从凭证解析（SEC-02），网关故障不影响既有会话语义。

### 6.2 鉴权方案落地（SEC-01/02/03 及配套）

| 边界 | V1.0 方案 | 对应发现 | 验收方法 |
|---|---|---|---|
| 设备 → M3 | HMAC(secret, deviceID + nonce + timestamp)：凭证 DB/KMS 加载、时间窗校验、nonce 缓存防重放、双槽轮转与吊销 | SEC-03 | 重放旧报文被拒；篡改 nonce/timestamp 被拒；吊销后旧凭证失效 |
| 设备 → M3（传输） | WSS over TLS 强制；CheckOrigin 白名单 + 子协议版本校验 | SEC-04/05 | 明文连接被拒；非法 Origin 被拒 |
| Agent → M10 网关 → M4 | API Key（哈希存储）+ 租户强绑定；租户上下文只取自凭证（网关仅透传不解析，SEC-02） | SEC-02 | 无/伪造凭证 401；跨租户请求 403 |
| 审批人 → M5 | 回调 URL HMAC 签名（ticket_id+decision+expire）+ 一次性消费 + OAuth 身份取真实 approver + 租户绑定校验 | SEC-01/21 | 无签名 401；伪造签名被拒；审批记录含真实主体 |
| 节点间 → Valkey | ACL 按节点账号最小权限 + TLS + 通道消息签名 | SEC-06 | 无凭据连接被拒；伪造响应被校验 |
| 管理员 → M10 网关 → M1 | HTTPS + 用户名口令 + 会话 + 租户内 RBAC（SSO/OIDC+MFA 为 EE 演进）；网关透传会话校验 | 新增 | 未登录 401；越权操作 403 |
| 平台 → 通知渠道 | webhook key 环境变量/密钥注入，ps 无明文；重试+告警 | SEC-13/18 | 源码与进程参数零密钥；失败有告警 |

配套基线：HTTP 服务全量超时 + body 大小限制（SEC-19）；ID 格式白名单校验（SEC-20）；mock 设备凭证环境注入（SEC-25）；依赖漏洞扫描（govulncheck）与密钥扫描进 CI。

### 6.3 审计链路（SEC-07/08）

- 事件最小字段集：tenant_id、agent_id（真实主体）、device_id、tool_name、request_params、response 摘要、status、hitl_approver（真实身份）、risk_level、traceId、时间戳；事件 ID 唯一约束保证幂等。
- 三条触发路径全覆盖：工具调用（M4 发起/结束双事件）、审批决策（M5，含拒绝/过期）、管理操作（M1，凭证签发/吊销/风险等级修改/审批流变更）。
- 异步缓冲落库（第 2.4 节流 3），审计记录原文存储不翻译（保证证据效力，doc/07 第 5 章）；控制台按语言渲染说明。
- 工单与审计为 PG 永久留存，消灭 24 小时 TTL 与重启丢失（SEC-08）。

### 6.4 限流（SEC-12）

见 5.2；补充：限流规则变更经 M1 配置并审计留痕；限流触发事件计入指标（Prometheus）便于容量告警。

## 7. 部署设计概要

### 7.1 Compose 拓扑与服务清单

V1.0 单机起步形态（默认交付，ADR-09）：全部服务单机容器化，网络分三段（edge 对外网段、app 内网段、data 私有网段仅 app 可达）。详细编排、持久卷、健康检查、离线安装包见 design/60。

| 服务 | 镜像/组件 | 端口（容器内） | 暴露 | 说明 |
|---|---|---|---|---|
| edge | nginx（静态资源 + TLS 终结） | 80/443 | 对外 | 托管 M2 前端；其余流量统一反代至 M10 网关（仅 nginx 暴露宿主端口） |
| gateway | M10 进程（Go） | 8090 | 经 edge 对外 | 前端唯一入口：路由/鉴权透传/限流/契约校验；无状态可多副本 |
| admin-api | M1 进程 | 8081 | 仅内网 | 控制面 API（经网关路由，不直连） |
| agent-api | M4 进程 | 8080 | 经 edge→网关对外 | Agent 端点（TLS） |
| connector | M3 进程 | 8443 | 经 edge→网关对外 | 设备 WSS（TLS） |
| approval | M5 进程 | 8082 | 经 edge→网关对外 | 审批回调入口 |
| audit | M6 进程 | 8083 | 仅内网 | 审计消费与查询 |
| py-agent | M9 进程（FastAPI/uvicorn，Python 3.14） | 8091 | 仅内网 | V1.0 最小集为开发/CI 工具不入生产拓扑（此行为 V1.5 完整 Agent 面预留）；经网关 /v2/agents/* 路由 |
| llm-gateway | M7（litellm） | 4000 | 经 edge→网关对外（可选） | 旁路，可整体不部署 |
| postgres | PostgreSQL 16+ | 5432 | 仅 data 网段 | 状态与审计主存 |
| valkey | Valkey 8+ | 6379 | 仅 data 网段 | 路由/唤醒/缓冲/限流（ACL+TLS） |

拆分部署形态：上述 app 服务可独立扩容（agent-api 无状态多副本；connector 多副本 + 设备分配策略；approval 单写者约束见 3.5；gateway 无状态多副本，edge nginx 上游健康检查）；一体二进制形态：M3/M4/M5/M6 装配为 adc-server 单进程 + M1 控制面进程 + M10 网关进程（独立，保证入口单一与故障隔离），共 3 个业务进程（私有化极简交付，ee/ 交付包目标形态）；M9 生产服务 V1.5 起装配（V1.0 评测工具链独立运行，不并入 adc-server）。

### 7.2 多架构支持

- 全部镜像经 buildx 构建 linux/amd64 与 linux/arm64 双架构（Go 交叉编译原生支持；前端静态资源架构无关）；Python 面（py-agent、评测工具链）经 uv wheelhouse（arm64 关键依赖 pydantic-core/cryptography/uvloop 均有预编译 wheel，design/70 2.5）固化依赖后多架构构建；基础镜像选用官方多架构变体（Valkey、PostgreSQL 官方镜像已覆盖）。
- 私有化交付包按客户现场架构选择单架构离线包；SaaS 侧镜像仓库以 manifest list 发布。

### 7.3 详细设计指向

Compose 编排细节、TLS 证书注入与轮转、持久卷规划、备份恢复、离线安装包制作、监控告警部署、升级与回滚流程——全部归 design/60《部署方案》，本文件不重复展开。

## 8. 风险与遗留

### 8.1 V1.0 范围内风险清单

| 风险 | 等级 | 缓解措施（V1.0 内） |
|---|---|---|
| Valkey Pub/Sub 过渡期仍存在静默丢消息面（业务消息不持久） | 高 | 关键事件一律走 List 缓冲（审计）+ 请求应答超时兜底 + 唤醒失败退化为超时 fail-safe；消息抽象接口保证阶段 2 可替换；SEC-10/14 修复验证作为发布门禁 |
| 路由索引与进程内会话双源漂移（GAP-11） | 高 | 会话归属以 Connector 本地为唯一权威，Valkey 索引为可重建派生数据；TTL 续期 + 断连主动清理 + 会话指针校验（SEC-14/15） |
| 单机 Compose 无高可用，与 99.9% SLA 假设存在差距 | 高 | V1.0 明确单机形态定位（ADR-09），SLA 承诺仅适用于拆分部署；阶段 2 压测与集群形态兑现或重估假设 |
| DBRiskPolicy 过渡期风险判定依赖工具元数据正确性（设备谎报 risk_level） | 中 | 平台权威覆盖：默认等级 2 先审后用；M1 可强制覆盖；设备上报仅作建议值（doc/07 2.4 双层模型）；声明与行为不符设备自动降权（V1.5 完善） |
| 团队对 Valkey ACL/TLS、多进程装配的新组件熟悉度 | 中 | 阶段 0 培训与演练；Compose 单机默认关闭跨机通道（本地直连优先路径），降低配置复杂度 |
| i18n 词条覆盖不全导致文案回退 | 低 | 缺 key 回退机制（en → zh-CN → 原文）；资源包 CI 校验（缺 key 阻断） |
| M10 网关成为外部入口单点（路由错误/契约误放行） | 中 | 无状态多副本 + edge nginx 健康检查；路由表配置驱动、变更经 design/33 评审与灰度验证；契约校验默认拒绝未声明字段；网关故障快速失败（5.5）不静默 |

### 8.2 V1.5+ 演进预留点（兼容性约束）
