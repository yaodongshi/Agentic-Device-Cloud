## 二、V2.0 任务拆解（细粒度）

### C1 协议适配器生态（核心，16 人日）
- C1.1 适配器插件框架：Adapter 接口（Discover/Capabilities/Read/Write/CallTool）+ 注册表 + 独立进程模式（Go plugin 备选）；ce/internal/adapters/
- C1.2 Modbus TCP/RTU 适配器（自实现或 goburrow/modbus）+ 模拟器测试套件
- C1.3 OPC-UA 适配器（gopcua 库）+ 模拟服务器测试
- C1.4 FANUC FOCAS / Siemens 840D 适配器（依赖厂商 SDK，接口占位+文档；真实联调与厂商合作线下）
- C1.5 适配器注册表 API + 控制台"协议适配器"页（列表/启用/健康状态）
- C1.6 适配器认证测试套件（每个协议一组标准测试：发现/读/写/风险映射）

### C2 OEM 白标与 SDK 生态（8 人日）
- C2.1 ee/ 白标模块骨架（品牌替换 seam：控制台 title/logo/色板经配置注入）

- C2.3 ESP32 C 内核完整版（承接 core-sdk/c/adc_edge.h 契约：WSS+TLS mbedTLS+JSON+OTA A/B——与硬件伙伴联合，代码骨架先行）

### C3 工具市场与开发者平台（8 人日）
- C3.1 工具包模型（adc_tool_packages 表：名称/版本/工具清单/签名）+ 发布/安装 API

- C3.3 开发者门户骨架（应用注册/A2A 编排器自助接入文档）

### C4-C5 平台化补全（10 人日）

## 五、M8 线下条件与发布边界

以下条件不以本地或 CI 的 `PASS` 替代，未完成时只能标记候选，不得创建正式 `v0.3.0` tag：

1. 使用至少一家真实客户 IdP 验证 issuer、私有 CA、MFA claim、回调域名和角色映射，确认未知身份默认拒绝。
2. 在原生 linux/amd64 与 linux/arm64 主机拉取三镜像，核对同一版本、digest、SPDX SBOM、签名和 CRITICAL 漏洞门禁。
3. 对 V2.0 既有 PostgreSQL 数据卷先备份再升级，核对迁移版本、哨兵数据、幂等重建和应用回滚；回滚不执行 down migration、不删除命名卷。
4. FANUC FOCAS、Siemens 840D、华中数控、ESP32 及真实 Modbus/OPC UA 设备继续作为硬件伙伴线下联调项，不因模拟器通过而宣称生产认证。
5. 归档 M8 全量门禁结果、Compose smoke、残余风险和批准记录后，才可创建 tag 与 GitHub Release。

## 六、战略基线复核

- 版本与许可保持三仓边界：`core-sdk/` 为 Apache-2.0，`ce/` 社区版为 LGPL-3，`ee/` 企业版为源码可见商业许可且禁止再分发。
- 设备主线为 A 类原生 MCP Server 设备 OAuth 2.1 客户端凭证绑定；本文 C2.3 的 WSS 路径仅定位为 B 类 SDK 桥接设备的 Legacy Bridge，C 类哑设备不直接支持。
- 技术栈使用 Valkey，不使用 Redis；MCP 管工具，A2A 管 Agent 协作；中英双语首发、社区英文优先，中国与全球双主场。
