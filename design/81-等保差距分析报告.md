## 一、报告说明

### 1.1 评估依据

1. GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》第三级安全通用要求（等保 2.0 三级）；
2. 测评方法参照 GB/T 28448-2019《信息安全技术 网络安全等级保护测评要求》；
3. 安全设计参照 GB/T 25070-2019《信息安全技术 网络安全等级保护安全设计技术要求》；
4. 内部基线：doc/05 第 2.4 节安全基线清单、SEC-01~25 评审发现；design/60 部署与交付方案（第 7 章安全加固、第 8 章备份恢复）；openspec/changes/phase0-security-hardening 变更执行状态；design/80 任务 A-06；design/10 SRS 合规条目（NFR-005）。

### 1.2 评估对象与责任边界

ADC 有三种交付形态，对应三种责任主体，本报告逐形态明确边界：

1. **SaaS 平台侧（ADC 自运营）**：ADC 为系统运营者，是定级与测评主体；云服务商提供的物理环境、云平台部分依赖云商等保测评结论（责任共担，需采购合同明确并索取测评报告摘要）。
2. **私有化交付（客户机房）**：客户为系统运营者与测评主体；ADC 作为软件供应商交付产品、部署方案、配置基线与配套文档证据包，测评所需的功能与配置由 ADC 产品承担。
3. **ADC 组织自身（研发与办公环境）**：安全管理制度类要求的建设主体。

本报告以"V1.0 软件交付物 + 部署配置基线"为评估对象，对照三级安全通用要求逐域分析；管理类要求同时覆盖上述三种形态的对应主体。

### 1.3 重要声明

- 本报告为**自评估**，非测评机构正式结论。正式等保三级测评在 **V1.5 前启动**（NFR-005；design/10 合规条目：V1.0 完成差距分析、V1.5 前通过测评）。
- 定级结论以正式定级备案为准；本报告按三级假设展开。
- 差距项编号 GAP-DJ-xx 为内部整改台账编号，非标准条款号；整改优先级分两级：**V1.0 前**（发布门禁）与 **V1.5 前**（测评门禁）。

## 二、现状摘要

### 2.1 安全工程现状（引用基线）

- **阶段 0 安全加固 18/20**（design/80 当前基线）。已完成：SEC-01 HITL 回调签名与一次性消费、SEC-02 Agent API Key 哈希存储与租户强绑定、SEC-03 设备 HMAC+nonce+时间窗防重放、SEC-04 CheckOrigin 白名单、SEC-08 审批工单 PG 主存、SEC-10 审批唤醒通道、SEC-11 CAS 原子更新与过期校验、SEC-14 路由 TTL 续期、SEC-15 设备重连踢旧连接、SEC-25 mock 密钥环境注入（openspec phase0 tasks 完成记录）。
- **待办 2 项**（design/80 A-06 为收尾项）：SEC-05 生产 TLS 强制（TLS 配置位已预埋，deploy/compose.yaml `ADC_TLS_ENABLE`，dev 默认关闭、生产经 secrets 挂载）；SEC-06 Valkey ACL 账户启用（ACL 配置文件 deploy/valkey-acl.conf 已在仓）；另有 SEC-07 审计写入链路（ce/internal/audit 目录已建、实现待完成）、SEC-12 限流中间件（ce/internal/ratelimit 目录已建、实现待完成）。
- **凭证与密钥**：设备 HMAC 密钥 KEK 加密落库（ce/internal/auth/secrets.go，AES-GCM encv1 存储形式，KEK 经 `ADC_DEVICE_KEK` 环境注入）；Agent API Key 哈希存储；会话口令 bcrypt（design/80 B-01）；gitleaks 密钥扫描进 CI（A-03）。
- **网络与运行时**：仅 nginx 暴露 80/443，postgres/valkey 零宿主映射；Valkey TLS 端口与 ACL 分账号；容器 distroless、非 root、只读根文件系统、capabilities 全 drop（design/60 第 7.3/7.4 节）。
- **审计与备份**：审计分区表 append-only、180 天留存可配置（design/32）；备份 RPO 5 分钟 / RTO 30 分钟方案与季度恢复演练矩阵（design/60 第 8 章、8.3 节）。
- **可观测与门禁**：Prometheus/Grafana/Loki 与告警规则（design/80 A-07/B-09）；CI 门禁含 lint/vet/test -race/覆盖率 70%/双架构构建/trivy 镜像扫描/syft SBOM/许可证扫描（design/80 A-03）。

### 2.2 与三级要求的结构性关系

三级安全通用要求分技术类（物理环境、通信网络、区域边界、计算环境、管理中心）与管理类（制度、机构、人员、建设、运维）。技术类依托 ADC 软件功能与部署配置达成，管理类依托 ADC 组织制度与交付文档达成。下文按此结构逐域分析。

## 四、结论

### 4.1 当前满足项清单（已满足或基本满足的三级要求）

1. **身份鉴别（部分）**：设备 nonce+时间窗防重放（SEC-03）、Agent API Key 哈希存储与租户强绑定（SEC-02）、口令 bcrypt 哈希、登录失败锁定设计（design/60 7.5）——满足 8.1.4.1 a/b/d 项主体要求（组合鉴别除外）。
2. **访问控制（部分）**：最小权限 RBAC、租户上下文从凭证解析、默认等级 2 先审后用（design/00 红线）。
3. **安全审计（设计满足、实现收尾中）**：审计要素设计（主体/对象/时间/结果）、append-only 分区表、180 天留存可配置、审批不可抵赖（SEC-08/21）。
4. **入侵防范（部分）**：最小安装（distroless、非 root、只读根、cap drop）、最小端口暴露、漏洞扫描进 CI（govulncheck/trivy）、高危 CVE 48 小时评估机制。
5. **数据保密性（部分）**：KEK 加密凭证存储、bcrypt、TLS 全链路设计。
6. **通信传输**：TLS 配置位与证书注入机制（收尾中）、Valkey ACL 配置在仓（收尾中）。
7. **区域边界（部分）**：nginx 加固（body 限制、限流、CheckOrigin 白名单 SEC-04）、宿主防火墙白名单、仅 nginx 暴露。
8. **数据备份恢复（部分）**：RPO 5 分钟/RTO 30 分钟方案、WAL 归档、异地备份、演练矩阵。
9. **恶意代码（缓解级）**：客户内网杀毒要求、SBOM 随包、镜像扫描门禁。
10. **集中监控**：Prometheus/Grafana/Loki、告警分级（A-07/B-09）。
