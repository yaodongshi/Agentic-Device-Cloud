# ADC V1.0 上线执行计划（四维度 + 开源现代化横切）

> 依据：doc/03 PRD（FR/NFR）、design/10~70 全套设计、design/50 项目开发计划、openspec 两个已完成变更
> 目标：V1.0 用户可用 = FR-001~010、013、014、018~020 + NFR-001/003/004/006 达标 + 开源仓库公开
> 颗粒度：任务级（1-3 人日/项，实施时逐项拆为 openspec tasks ≤2 小时）
> 当前基线：阶段 0 安全加固 18/20 + 方案 A 架构 12/12 完成；V1.0 功能约 35-40%

---

## 一、V1.0 发布标准（验收锚点，来自 doc/03 第 6 节与 design/00）

1. 2 家种子工厂试点运行 4 周无 P0/P1 缺陷；设备在线率 ≥99%；高危拦截率 100%
2. 审计留存 180 天验证通过；等保差距分析完成
3. 开源仓库公开：三仓（core-sdk Apache-2.0 / ce LGPL-3 / ee 源码可见）LICENSE 合规清零、CI 门禁通过、文档站上线
4. 控制台七大模块可用（FR-014）；统一 API 网关为前端唯一入口（ADR-19）

## 二、对标基线：LiteLLM / Open WebUI 的"最小现代化距离"（七条）

| # | 对标项 | 最小达标定义 |
|---|--------|--------------|
| B1 | 稳定发布节奏 | 语义化版本 + CHANGELOG + tag 触发发布，每月至少一个 release |
| B2 | CI 质量门禁 | 每次合并：lint + vet + 单测(覆盖率≥70%) + 构建双架构 + 镜像扫描 + SBOM 生成，任一失败阻断 |
| B3 | 文档站 | 官网式文档（快速开始 5 分钟跑通 + API 参考 + 架构说明），中英双语 |
| B4 | 贡献流程 | DCO + 贡献指南 + issue/PR 模板 + 讨论区，外部 PR 可自助合入 |
| B5 | 安全治理 | SECURITY.md + 漏洞披露流程 + 依赖扫描常态化 + 密钥零明文 |
| B6 | 可观测性 | /metrics + 结构化日志 + 请求 trace，告警分级 |
| B7 | 安装体验 | 一条命令安装（compose up）+ 健康检查自诊断 + 升级/回滚脚本 |

## 五、里程碑与验收门禁

1. **M1（Sprint 4 末）**：控制台可登录并纳管设备（F-02~F-04+B-02/03 验收过）

## 六、风险与决策点

1. **前端人日估算风险**：F-12 E2E 与 F-10 看板是前端的深水区，若滞后可先降级（看板 V1.0 只做两图，E2E 只留 2 条核心流）
2. **边缘 C 内核（E-04）**：ESP32 完整版属 V1.5，V1.0 只承诺演示级；种子客户以 Linux 盒子 SDK（E-02）为主
3. **双架构 arm64 实测（A-04）**：无 arm64 主机时用 QEMU 模拟冒烟，标注为"构建验证+模拟冒烟"
4. **团队规模假设**：10 人（后端 4+前端 2+边缘 1+测试 1+DevOps 1+产品 1）；若 5 人则周期翻倍至 7-8 个月
