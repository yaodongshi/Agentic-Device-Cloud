## 阶段 B：V1.5 九大块（约 4-5 个月）

### B1. FR-011 设备批量纳管（5 人日）
- B1.1 后端：CSV 导入端点（POST /v1/admin/devices/import，异步任务+逐行错误报告，上限 1000 行）
- B1.2 前端：批量导入弹窗（模板下载/上传/进度/结果页）
- B1.3 设备分组（CRUD + 分组维度查询/审批策略作用域）

### B2. FR-017 监控告警增强（4 人日）
- B2.1 告警规则可视化配置（控制台页：阈值编辑写 Valkey/PG，Prometheus 动态加载）
- B2.2 告警通知渠道（邮件+群机器人，复用 Notifier seam）
- B2.3 告警历史与确认（ack/静默）

### B3. FR-016 计费上线（8 人日）
- B3.1 计费引擎：usage_events 聚合（日/月账单，按 doc/04 三档定价公式）
- B3.2 账单 API + 控制台账单页（明细对账/导出）
- B3.3 配额联动：账单欠费/超额策略（软限制→只读降级）

### B4. FR-012 LLM 网关（10 人日，Python 面）
- B4.1 LiteLLM 部署与托管（compose 服务 + 多供应商配置）
- B4.2 ADC 接入层：/v1/llm/* 代理（网关路由 + 计量 seam MeteringHook）
- B4.3 供应商故障转移 + Token 计量归集 + BYOK 支持

### B5. FR-021 原生 MCP 设备接入（12 人日）
- B5.1 设备注册治理：MCP 端点登记 + OAuth 2.1 客户端凭证绑定（doc/07 七步流程）
- B5.2 平台侧 MCP 客户端实现（官方 Go SDK 或自实现 Streamable HTTP 客户端）
- B5.3 绑定生命周期（心跳/吊销/解绑）+ 工具目录同步
- B5.4 A 类设备厂商联调（≥2 类）

### B6. FR-023 全栈 i18n UI（6 人日）
- B6.1 控制台英文词条全量补译 + 语言切换开关
- B6.2 后端错误消息 i18n 键（当前中文硬编码）+ 审批卡片/通知多语言
- B6.3 日期/时区/单位本地化验证（en-US 回归）

### B7. FR-022/024 A2A 与多 Agent 编排（14 人日，Python 面）
- B7.1 Agent Card 发布（GET /.well-known/agent-card.json，双语）
- B7.2 A2A 任务端点（POST /v2/agents/a2a/tasks，任务状态机 + HITL 语义映射 input-required）
- B7.3 内部四 Agent 流水线（Planner/设备选择/执行/HITL 审批，LangGraph 或自研，doc/07 评测基线）
- B7.4 评测集建设（≥50 用例，doc/07 四轮评测法）+ 外部编排器联调 ≥1 家

### B8. NFR-005 等保 2.0 三级测评（12 人日，含整改）
- B8.1 design/81 差距整改（V1.0 前 13 项清单执行）
- B8.2 测评机构选型与预评估
- B8.3 正式测评 + 整改闭环 + 证书

### B9. 私有化交付包（6 人日）
- B9.1 离线安装包（镜像 save/load + wheelhouse + 一键脚本，design/60 4.x）
- B9.2 License 心跳计量（ee/ 首模块：License 服务 + 超期降级）
- B9.3 私有化升级/回滚演练

## 执行规则

1. 每块经 openspec 变更流转（/opsx-propose → apply → archive），tasks 沿用本文子任务编号
2. 优先级顺序：A（收尾）→ B1/B2（快赢）→ B4/B5/B7（技术纵深）→ B3/B8/B9（商业化）→ C
3. 每个子任务验收必须可判定；跨块依赖以"前置"列为准
4. 本文档与 design/50/80 的关系：50 是 Sprint 编排、80 是 V1.0 执行、本文是全量细节拆解总表
