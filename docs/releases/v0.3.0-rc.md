# ADC v0.3.0 候选发布说明

> 状态：候选，尚未创建 Git tag 或 GitHub Release。适用于 V2.1 M8 本地和预发验收。

## 候选内容

- 提供 Modbus、OPC UA 适配器框架及工具市场链路。
- 提供白标配置、预算状态、工具参数校验和中英翻译质量门禁。
- 收敛 OIDC 生产安全、数据库迁移生命周期和开发者应用自助接入能力；最终完成度以 M8 验收记录为准。
- 发布 ADC、Python Agent、Console 三个同版本多架构镜像，并为每个平台生成 SPDX SBOM。

## 候选验证

1. 执行 `bash scripts/pre-release-check.sh v0.3.0`，确认源码、SDK、i18n、迁移和版本门禁通过。
2. 将三镜像按发布 digest 预加载或映射为 Compose 使用的 `adc/ce:0.3.0`、`adc/py-agent:0.3.0`、`adc/console:0.3.0`，设置 `ADC_VERSION=0.3.0` 后执行 `docker compose -f deploy/compose.yaml up -d`；禁止在候选环境现场重新构建。
3. 执行 `bash scripts/dev-smoke.sh`，确认原有 10 项主链路及迁移、OIDC 状态、工具市场和预算专项检查无失败；参数越界项如显示 `SKIP`，须以脚本列出的自动化测试门禁结果补充证据。

## 升级与回滚

- 升级前备份 PostgreSQL 命名卷并记录当前迁移版本；迁移只向前执行，不运行 down migration。
- 专项冒烟失败时，将 `ADC_VERSION` 回切到升级前的不可变版本并重新执行 `docker compose up -d`，不得删除 PostgreSQL 或 Valkey 命名卷。
- 仅在确认数据损坏时从升级前备份恢复；应用回滚不能替代数据恢复演练。

## 正式发布前条件

- 完成真实客户 IdP、原生 linux/amd64 与 linux/arm64、既有 V2.0 数据卷和工业硬件线下验收。
- 归档 M8 门禁证据与残余风险，用户批准后再创建 `v0.3.0` tag；本候选阶段不创建 tag。
